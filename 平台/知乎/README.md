# 知乎草稿助手

把本地文章自动保存进知乎草稿箱。程序使用知乎编辑器自带的**「导入 → 导入文档」**把 Word 读进正文，
**Word 里的图片会一并由知乎自己上传**，不需要单独传图；写入后重新打开草稿，核对标题、正文和配图数量，
成功后将原文件移入“已发文章”。程序没有公开发布功能，不会点“发布”。

## 使用方法

1. 首次双击 **01-登录知乎.cmd**，在打开的专用 Edge 窗口里手动登录知乎。看到终端显示登录成功即可。该窗口使用独立配置，登录状态保存在本项目中，之后无需每次重新登录。
2. 将需要发送的 `.docx`、`.md` 或 `.txt` 放入 **待发文章**。带图的成稿由「文章总库」调取进来：
   在 `项目根目录` 双击 **01-排版图文.cmd** → **02-调取到知乎.cmd**。
3. 双击 **02-保存一篇到草稿箱.cmd** 试运行；批量处理时双击 **03-全部保存到草稿箱.cmd**。
4. 去知乎草稿箱检查内容。**已发文章**表示“已保存到草稿箱”，并不表示已经公开发布。

本机已安装 Python 与 Playwright。换电脑时先安装 Python 3.10 或以上版本，并运行 `python -m pip install -r requirements.txt`；电脑需要安装 Microsoft Edge，不需要额外下载 Chromium。

## 图文与封面

- `.docx` 走知乎的「导入文档」：打开写文章页 → 导入 → 导入文档 → 选中成稿，正文和配图由知乎读进去，
  图片自动上传到知乎图床（首次使用会提示文件存在你的「我分享的文件」里，这是知乎自己的机制）。
- 知乎的导入**不带标题**，所以程序导入完成后会自己把标题写进标题栏，再等待自动保存。
- 封面自动匹配：文章总库排版时已经把选定的封面放在成稿最前面，程序会把这张图上传到「发布设置 → 添加封面」；
  知乎的封面控件偶尔加载较慢，没赶上时终端会提示你手动选一下，草稿本身不受影响。
- 保存与否不看界面提示，而是**另开一个页面**把草稿整篇读回来比对：标题一致、正文一致（忽略图片注释占位）、
  正文图片数量一致，三条都满足才算成功并归档。
- 导入比较慢（每张图都要平台自己上传），一篇 7 图的稿子大约 1~2 分钟，请耐心等，不要关闭专用窗口。

## 文件和进度

| 位置 | 用途 |
| --- | --- |
| 待发文章 | 准备送入草稿箱的原文；上传失败留在这里 |
| 已发文章 | 保存并回读验证成功的原文 |
| 重复文章 | 与已处理文章内容相同的副本，复用已有草稿 |
| 预览 | 双击 `04-生成文章预览.cmd` 后生成的本地网页和清单 |
| data/drafts.sqlite3 | 保存状态、内容指纹、草稿地址和异常记录 |
| data/*.json | 每篇保存成功的回执与草稿链接 |
| data/edge-profile | 专用 Edge 登录状态；请勿上传、分享或删除 |
| logs | 异常诊断信息和截图 |

## 保存规则

- 支持正文段落、小标题、粗体等基础富文本格式。
- Word 里的图片会按文档顺序导入并按顺序上传；表格、公式、修订等未支持内容会明确报错，避免丢失内容后继续上传。
- Markdown 是基础语法支持，图片等复杂内容会报错；纯文本建议以 `标题：文章标题` 标记标题，否则用文件名，正文完整保留。
- 每篇之间默认间隔 12 秒。运行期间不要在专用窗口里同时编辑文章。
- 同一份内容重复放入待发目录，不会重复新建草稿。该去重记录只覆盖本系统处理过的文章，不能识别你此前手动上传的所有历史草稿。
- 编辑器里如果已经有别的内容，程序会停止而不是覆盖它；确认不要了可以加 `--清空编辑器` 再运行一次。
- 遇到登录失效、验证码或页面变化，程序会停止并保留原文。验证码和登录由你手动完成。
- 保存后中断、但已经记录草稿地址时，下一次会先打开同一地址核对。若只有半篇或内容不符，会保留待发文件并停止，不覆盖草稿。
- 若上传中断且没有记录到草稿地址，程序会要求先人工检查草稿箱，避免结果不明时再新建。请在 Codex 中提供对应文章及草稿链接协助恢复。
- 不要删除 `data` 目录，否则会丢失去重和断点记录。原文在上传过程中被修改时不会归档。

## 当前 Edge 与专用 Edge

Codex 可以通过已连接的浏览器扩展操作你现在登录的 Edge。双击脚本在 Codex 之外运行时，使用本项目的专用 Edge 配置，首次需要手动登录一次；两者的登录状态不混用，也不会读取或复制日常 Edge 的 Cookie。

高级用户可通过 `--cdp http://127.0.0.1:9222` 连接已经启用本机调试的 Edge。程序不会自行关闭日常 Edge，也不会开启对外监听。有关调试连接见 [Microsoft Edge 官方文档](https://learn.microsoft.com/en-us/microsoft-edge/devtools/protocol/)。

## 命令行

在本项目目录运行：

```powershell
python -X utf8 -m zhihu_drafts init
python -X utf8 -m zhihu_drafts list
python -X utf8 -m zhihu_drafts preview
python -X utf8 -m zhihu_drafts login
python -X utf8 -m zhihu_drafts run --limit 1
python -X utf8 -m zhihu_drafts run --limit 0
python -X utf8 -m zhihu_drafts run --limit 0 --清空编辑器
python -X utf8 -m zhihu_drafts probe
python -X utf8 -m unittest discover -s tests -v
```

浏览器离线集成测试可先执行 `$env:ZHIHU_BROWSER_TESTS='1'` 再运行测试命令。测试在本机 Edge 中拦截所有请求，不操作真实知乎账号。

`init` 只整理项目根目录的 Word 文件，不会把项目说明文件当成文章。`run` 默认最多保存一篇；`--limit 0` 处理全部；`--清空编辑器` 表示允许先清掉编辑器里残留的临时内容。整个批次遇到错误会停止，不跳过错误悄悄继续。`probe` 会把当前编辑器结构写进 `logs/editor-probe.json`，知乎改版时用它反馈即可修复。
