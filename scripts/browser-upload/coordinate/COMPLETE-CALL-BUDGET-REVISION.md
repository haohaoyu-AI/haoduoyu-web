# Complete-call budget revision

On 2026-10-11 the internal native definition allocation changed from 24,000 to 28,000 UTF-8 bytes. The retained native step session now preserves `validate -> ready -> single physical commit`: awaited readiness reads finish before the parent rechecks cancellation and current authority, then issues the separate one-action commit. Removing this fence to fit an internal size target would weaken the Open boundary.

The earlier failure remains part of the record: one compiled primary native definition measured 24,101 UTF-8 bytes against the former 24,000-byte bound and was rejected by 101 bytes. That measurement contained no actual adapter, initialization or whole tool request and did not verify a complete call. The revised bound does not turn that failed measurement into approval.

The current internal component bounds are definitions 28,000 bytes, actual adapter 20,000 bytes and initialization 8,000 bytes. An 8,000-byte transport reserve is only a plan; it is not an additional hard limit and does not prove the real request fits. The exact separators, JSON escaping, all actual tool arguments and known wrapper overhead count toward the unchanged strict 64,000-byte limit. Both complete ordinary code and the entire actual JSON request plus wrapper must fit; 64,000 is permitted, 64,001 is refused with the frozen measurement report retained.

Source readers report `complete_call_budget_verified:false`. Only a parent-memory measurement with all actual source components, exact matching top-level code field, actual tool arguments and known wrapper bytes can report that this supplied snapshot fits. Missing inputs remain unknown. A measured fit is not normal original-host approval, adapter availability, native closure or platform acceptance. Changed inputs require a new complete measurement before submitting the complete ordinary call for normal approval. No VM, dynamic loader, minification, encoding or execution fragments are introduced.

An offline definition-only snapshot on 2026-10-11 measured the current two-file primary compilation at 25,567 UTF-8 bytes and 25,857 JSON-quoted bytes, leaving 2,433 bytes of the revised definition allocation. The actual complete payload remained `null` and `complete_call_budget_verified:false` because adapter, initialization, whole tool arguments, code-field binding and known wrapper were absent. This is a recorded snapshot; changed source needs a new measurement.

The offline synthetic complete-call sample measured ordinary code 48,004 bytes, whole JSON request 48,037 bytes and explicit synthetic wrapper 400 bytes: payload 48,437, remaining strict budget 15,563. It reported `normal_host_approval_granted:false` and made zero real host calls. A separate negative test fills all three component allocations and supplies an 8,000-byte wrapper; the complete request exceeds 64,000 because exact separators and JSON overhead also count, so the helper retains a failed report.
