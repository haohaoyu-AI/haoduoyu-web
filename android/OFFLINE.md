# 原生离线版架构与验收边界

版本：`2.0.1` / `versionCode 3`。本轮修复匿名公开工作台同步；修正版的 CI、签名和 Library 文件独立核验。2.0.0 的本地原生能力已交付，但旧测试未证明匿名同步，不能作为本轮验证证据。尚未实机验收。

## 首版移动体验

启动进入本地原生工作台，无需等待远程网页首屏。待办、生活/工作碎碎念和备忘录读取本机状态，保存先落盘，网络同步独立显示。

待办支持日期、新建、圆形勾选和长按删除；已有线上待办文字不能原位编辑。碎碎念是稳定 UUID 独立条目，旧按日期日记保留独立身份，不按相同日期或文字合并。备忘录保留组/笔记关系，首版不做跨组移动和组批量删除。

模块、日期、列表位置与草稿持久保存。连续输入按编辑器合并待写草稿；创建/编辑与清空相应草稿在同一事务完成，成功后才结束保存流程，失败保留输入。低频功能沿用原 WebView，网页草稿行为由原站提供；所有模块共用原线上源，没有第二套后端。

## SQLite 与原子提交

状态包含已确认基线 `server`、当前可见 `local`、身份、草稿、位置、outbox、冻结请求、冲突副本和隐藏同步暂存。候选副本写入成功后才替换内存已提交状态。

内部数据库 `haoduoyu-offline.db` 将 UTF8 状态拆成最多 256 KiB 的 BLOB，写入 `offline_chunks`；`offline_manifest` 记录总字节、SHA256、块数。清单和所有块在同一事务替换，失败回滚保留旧状态。

读取在同一事务验证连续索引、顺序、长度、块数、总字节和摘要，再严格解码 UTF8，避免整条大 TEXT 超过 CursorWindow。上限 32 MiB，缺块、坏块、超限或未知格式拒绝读取，不清库。

串行的本地状态存储使用单连接 DELETE journal，并设置及读回核验 `synchronous=FULL`，确保配置覆盖实际读写连接。自定义损坏处理器避免 Android 默认删除数据库，保留原数据库及可能存在的 DB/WAL/SHM，不自动重建。系统应用备份禁用；卸载/清除数据会删除未同步内容，本版尚无完整数据库备份/恢复界面。

## 稳定身份与冻结队列

线上实体保留原 ID，本机新待办、碎碎念和备忘录组/笔记用 UUID；操作另有稳定 `op_id`。只有明确从未发出的队尾编辑可合并，已冻结操作不能改变方法、路径、请求体、版本或 ID。

发送前持久冻结 `wire` 再请求。超时、断网不能证明服务端未执行；重启恢复原请求，不生成新操作 ID。队列顺序提交，只确认队首已冻结操作，重复确认旧操作不消费下一项。较早操作确认时保留之后的本地编辑，每次确认后重新对账，再选择后续版本。

父组创建先于笔记创建。线上父组删除可能不增加子笔记源版本，仍须比较有效墓碑、内容 hash 和时间。普通编辑不自动复活删除实体。

## 复用原 API

使用固定 HTTPS 站点、`/api/v1`、原会话和 CSRF，没有新增长期 API key。

| 类别 | 既有契约 |
| --- | --- |
| 待办 | 客户端 UUID、版本 CAS、软删；同 ID/内容创建可重放；PATCH 完成 |
| 新碎碎念 | `/note-entries`、版本、`save_id`、独立 operation 收据 |
| 旧日记 | `/daily-notes`、分类/日期、版本和 `save_id`；无独立收据 GET |
| 备忘录 | `/memos` 组/笔记、版本、`save_id`、独立 operation 收据 |
| 工作台读取 | `/workbench-snapshot/index`、`/workbench-snapshot?date=YYYY-MM-DD` |

操作 ID 防重复，版本防并发覆盖。待办完成没有独立收据，未知结果须读回精确版本、目标状态和验证过的当前记录；无法确定时保留冲突。旧日记保守重放原请求并读回。

收据可能属于被其他设备继续修改的旧结果，仍要核对当前快照。收据数据库行 hash 与规范化投影 hash 不同，不直接混用。

## 完整清单与分段对账

清单包含待办、生活/工作旧日记、新碎碎念、工作提醒、备忘录组/笔记和软删墓碑，提供 `entity_id`、`content_hash`、`scope_id`、manifest、全局及日期 hash。

先读 index，复用验证过且未变正文，按需读缺失/变化日期；日期响应包含无日期备忘录。已验证分段存入隐藏 `sync_stage`，不提前替换用户可见数据。

单轮最多 32 请求、4 写入、60 秒，剩余工作保存暂存继续后续任务。结束时重读 index，范围、manifest 稳定且所有实体验证完整后，才一次事务应用。部分下载、断网、某页失败或清单竞争都不会清空旧数据或伪称完整同步。

现有服务器预算含 4000 源行、1000 日期、单次 1 MiB 源 JSON/响应等；超限失败并保留缓存和队列。本版是个人小规模完整对账，不用本机时钟或简单 `updated_at` 查询冒充稳定增量游标。

工作台清单不含待办模板/链接、偏好和图文；低频网页能力保留，不宣称这些已纳入原生离线同步。

## 冲突、墓碑和公开工作台范围

冲突保存原基线、本地、线上及原操作，本人核对后处理。采用线上版本时仍在冲突记录保留本地内容和相关操作；支持类型可复制为新 UUID，不复活原实体。备忘录父组不可用时保留内容，不写回被删父组。

更旧快照不能回滚已确认版本。首次联网核对网站 `publicBusiness: true` 与 `id: public-business`，再从完整快照核实 `scope_id`。固定 HTTPS origin + scope 的派生公共身份，先拉取已有记录，不冻结或发送本机队列。用户明确允许当前公开目标后，写请求才携带 `Origin` 与 `X-Public-Business: 1`；wire 同时固定 identity_mode、origin、派生身份与 scope。非公开身份、目标变更、旧私有/未知冻结请求均暂停，不改绑、不重写。401/403 保留数据并提示公开访问或编辑权限问题，不提示不存在的登录门槛。

## 图文和提醒边界

图文仅缓存实际获取的 published 记录元数据：标题、链接、摘要、备注及已有流水线字段。缺项不直接推断删除，不宣称覆盖所有状态和最新精确硬删。

现有接口不提供完整原文和图片二进制。图片数量、封面描述或草稿引用不等于下载过素材。提醒只显示已获取日期摘要，不生成未缓存数据，不新增系统定时通知。

首版无需改后端。后续统一图文全状态增量、精确硬删及完整原文附件离线，单独讨论原数据库/API 的兼容扩展。

## 自动重试与 Android 限制

网络失败、限流和临时服务异常带退避重试并保留原冻结操作。联网恢复、回到 App、手动同步和系统任务可触发后续尝试；“已存本地”和完成确认/对账的“已同步”分别显示。

JobScheduler 使用网络约束、恢复任务和最短 15 分钟周期，持久任务由系统在重启后恢复。Doze、省电、配额、厂商限制和网络会延迟，周期不保证准点。强制停止后需重新打开 App，不绕过系统限制。

仅申请三个普通权限：`INTERNET` 访问原站，`ACCESS_NETWORK_STATE` 感知网络，`RECEIVE_BOOT_COMPLETED` 支持持久 JobScheduler。无新增相机、麦克风、定位、通讯录、共享存储、通知、精确定时闹钟权限。

既有检查覆盖核心状态原子保存、冻结队列、墓碑、SQLite 分块重开、坏块拒绝、写入回滚、FULL 持久模式、原生输入/完成/草稿与保存防重。2.0.1 另外加入真实匿名 worker 入口、客户端公共身份与权限、origin/scope 隔离、离线队列恢复和旧 2.0 SQLite 保留升级检查。本轮结果以修正版 CI 为准；不包含真实手机或生产公开工作台端到端写入验收。

自动化不代表实机验收。还需测试冷启动、无网读写、中文输入法、键盘、勾选/长按/返回、切后台/重启、日期/位置、网络恢复、网页并发、删除、会话和后台延迟。使用测试数据，不自动写入生产记录。
