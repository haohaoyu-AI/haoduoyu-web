## 旧客户端差分

`tests/legacy-read-contract.test.mjs` 从 Git 只读归档上述历史提交，在临时目录用相同的已审阅 build 脚本和锁文件依赖构建旧 Worker。不会提交历史源码包或生产数据。

读接口由旧、新 Worker 使用同一合成 D1、真实 Cookie 或真实受限 Bearer 凭据执行；写接口各在独立、相同状态的新空库副本上执行。克隆仅在测试层复制明确的合成行，不调用或放宽生产备份恢复机制。初始化另用全新空库和测试专属初始化凭据。认证及 scrypt/CSRF/会话效果未模拟；比较期间固定两个 Node Worker 的时钟以消除生成时间差异。

覆盖集合与 OpenAPI 方法清单做集合断言，不只比较数量：

- 14 个文档化 GET：/health、/openapi.json、/api-docs、/api/v1/auth/me、/accounts、/articles、/articles/{id}、/observations、/daily-metrics、/dashboard、/api-keys、/audit、/export、/overview。除前三项外均为 /api/v1 前缀。
- 另加既有未列入 OpenAPI 的 GET /api/v1/backup。共 15 路由 × 会话/Bearer 两种上下文，即 30 组旧新比较。明确断言成功 200，Bearer 管理员专属入口为 403，再比较旧字段、HTTP 状态、响应头；非 JSON 内容逐字节比较。备份只含合成值，不存盘，不在失败诊断回显其哈希内容。
- 11 个文档化写方法：POST 登录/退出/账号/文章/快照/每日数据/凭据，PUT 密码/账号/文章，DELETE 凭据；另加既有 POST /api/v1/bootstrap。共 12 组旧新真实执行比较，使用原有请求字段，不添加新参数。
- 写响应只对实际随机生成的账号/文章/快照/凭据 ID 校验非空不透明字符串后规范化；一次性凭据验证格式，登录 Cookie/CSRF 验证格式与真实派生关系后规范化。每日记录的确定性 ID、其他字段、状态和响应头仍直接比较。不是声称随机值原始字节相等，也不由本测试证明随机源强度。
- 登录后真实新 Cookie 可访问 /auth/me，退出和改密后旧会话被拒绝；初始化后实际登录可用。并发、过期、撤销和限流等由既有功能测试补充。

读 JSON 投影只移除 B1 的 id、B2 的 entity_label；OpenAPI 只复原版本号、当前身份引用并移除指定新增模型/属性后对照。其余 JSON 结构与旧值必须一致。这个差分使用一套包含真实 0 与 likes/approvals 的合成状态，不冒充所有数据规模、参数排列或生产实测；其他数据变体由既有 analytics/overview/contract 测试覆盖。
