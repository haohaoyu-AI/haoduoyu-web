## 正式读取合同

已知c30源 `c30a8a956715b6ea809db4b87c0f4fcddf8f61de` 的records/overview/analytics及公开OpenAPI定义四个独立GET：

- `/api/v1/overview`：account_id、period（yesterday/7d/30d）、top_n（1–100）、top_platform。平台筛选只影响累计榜。
- `/api/v1/due-reviews`：account_id。同篇文章的D1、D3、D7是三个独立节点，键为文章与due_kind组合。
- `/api/v1/observations`：account_id、article_id。累计快照按来源截至和采集时间保留；原响应不含账号字段，账号绑定依赖正式查询及工作区校验，不虚构响应内证明。
- `/api/v1/daily-metrics`：account_id、from、to（真实日期、闭区间）。账号整体与文章明细分行，不能相加为账号总量。

四个接口没有分页合同。精确参数白名单与共享原生解析器同时执行，拒绝被源忽略的page/stage等参数。默认总览维持原无参数缓存键；未知合法metadata保留。网络原始响应仍限1MiB，本机Unicode编码读取另限8MiB/10000行，超限整体失败，不截断或放宽源合同。

## 已实现

四个原生标签页、账号选择、完整周期与榜单筛选、文章标识与每日日期筛选；切页只读本机精确查询副本，显式应用/刷新才联网。累计快照卡片、指标覆盖、账号本期/上期值与比较原因、累计榜、关注原因、到期观察、缺资料文章、真实逐日表、平台比较与系列资料分别展示。累计和每日新增不混加，缺日不补零，likes不冒充知乎approvals；未提供、历史空值与真实0区别显示。不在本机重算业务聚合或改判关注状态。

只读条目与导出保留来源字段和当前查询。文章摘要无完整可写版本；打开原文章须单独GET、复核身份与版本，再复用已有完整详情及同key原草稿。Unknown/恢复请求先进入原同步核对围栏，不能借摘要重基或重发。未新增无CAS的旧统计写表单。

每次异步读取/解析/缓存前后均核对身份、scope、Engine、store、页面epoch和取消。四个独立响应各有来源，不声称跨页面同一事务快照。400、413、坏成功响应、取消、外来scope和资料超限保全旧副本、草稿和队列。
