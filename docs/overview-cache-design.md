- 鉴权会话过期独立于业务revision，每次请求和一致读重试仍须真实鉴权。时钟倒退保守miss，不把未来结果给过去请求。

## 拟定最小实现

缓存完整成功JSON的私有不可变Blob，只缓存正文，不缓存actor对象、Cookie/token/token_hash/CSRF或响应身份头。键按DB对象身份、revision、验证不改变错误优先级的规范化overview查询、actor种类/id/完整scope/permissions摘要隔离。无关参数不能把凭据原值放进缓存键。

有效区间从计算时刻起，到“下一北京日界、下一未完成观察到期、下一合格保险成员发布时间”的最早事件，右端不包含；不使用近似TTL。误差无法证明不存在时不缓存，不改业务输出。未来/过去时钟均与旧版同输入对照。

consistentRead仍原样做首尾revision检查与重试；只向内部operation传入当前尝试before，不能复用第一轮revision给重试。miss结果先暂存，只有稳定读与既有C2使用时间更新都成功后发布；失败/被弃尝试取消正文并释放暂存，不发布可用缓存。hit仍经过鉴权和首尾检查。

拟定全isolate总预算16MiB、单项15MiB、最多50条，跨DB共同受总限额约束。驻留与待发布正文、响应仍持有的缓存正文均计入；活跃正文不能通过LRU驱逐逃掉计费。按UTF-8 Blob.size加键/元数据保守余量收费，超大/预算不足走完整未缓存响应，不截字段/历史。

Blob以最多64KiB分块读取，避免每次命中再完整stringify/复制正文；响应读完或取消释放引用。预算是可核验逻辑驻留，不等于GC死对象立即释放或目标峰值安全。需验证并发、取消、重试、更新失败均不泄漏引用或预算。

## 证据与未验门槛

单独纯缓存测试覆盖LRU/总字节/单项/活跃引用/超大拒收/不可变；集成用真实合成D1覆盖写后miss、DB/query/scope/权限隔离、北京日界、due各边界、保险发布、时钟倒退、混合账号日数据、认证/一致读竞态和错误不缓存。候选逐路对照旧版正文及字段，不只候选自身hash稳定。

大基准仍固定5000/20000/50000、首次+2预热+10正式、完整响应读取；旧/新同场配对，分列cache指标、D1、序列化及端到端。测试DB计数包装需保持同一底层绑定的稳定对象身份，且旧/新使用同一包装口径。不会把纯计算计时偷换成总耗时。

目标runtime峰值尚未验证。将尝试本地workerd inspector/堆指标，并区分Node进程、workerd V8堆及完整isolate外部存储；无法取得完整峰值时明确未验，不用Node577MiB作安全证明，不抬预算至数百MiB。现有14.6MB正文只有一个大项能占据大部分预算；50份载荷约696MiB的方案不采用。

## 资源状态与失败边界

- reserve：先计算完整 UTF-8 正文尺寸并预留预算，再分配 Blob；并发 pending 也占总预算。不能先各自创建大 Blob 后再查限额。
- pending：属于当前一致读尝试。revision 冲突、五次重试耗尽、鉴权或 C2 元数据更新失败均显式 abort；尚未发布的 Blob 在没有读取租约时立即移出记账并解除引用。
- resident：只有首尾 revision 稳定且 C2 成功后才发布。有效期仍从原计算采样时刻开始；计算期间越过截止点的结果可以供该请求返回，但不得发布给未来命中。
- response lease：最终 Response 在稳定读和 C2 成功后才创建。未消费、正在读取或被替换驱逐的活跃条目仍占预算；读取完毕或取消才归还租约。已驱逐但仍在读取的 Blob 要等最后一次异步读取完成才解除引用。
- 流每次最多复制 64 KiB，消费者修改收到的字节不会修改私有 Blob；不缓存 actor 对象或可变 JSON 对象。HTTP Content-Type 仍为 application/json，状态、完整 {data:...}、no-store 与安全头不变，不新增 Content-Length。
- 正文读取错误发生在 fetch 返回之后时，读取 Promise 拒绝，无法再由旧外层 catch 换成 JSON 500。测试注入仅存在于纯测试构造参数；生产使用本地不可变 Blob。此失败时机是新增流表示的明确限制，必须保留，不将故障说成正常 JSON 错误响应。

16 MiB 是活跃缓存 Blob、预留额度与每条保守元数据估算的记账上限，不是整个 isolate 的内存峰值。原有查询结果、JSON.stringify 临时字符串、流消费者自身保留的字节及运行时开销并不因此消失。单条超过 15 MiB 或当前预算不够时完整返回旧式字符串响应，不截断、不改窗口、不删除字段。垃圾回收的实际回收时点不能用逻辑记账冒充。

## 基准口径补充

候选与基线使用同一隔离 D1 数据、固定时刻和原 39 样本协议，逐路径对比完整正文哈希和状态。两种实现各自复用稳定的 D1 包装对象，包装器每次清空计数；旧基准每次新建包装器不适合验证按绑定身份隔离的缓存。交替旧/新执行顺序，其余端到端计时仍覆盖 Worker.fetch 到完整 arrayBuffer，不能省略 14.6 MB 正文读取。所有结果与失败样本都保留，正式结果另列，不覆盖阶段 0 或前置基准。
