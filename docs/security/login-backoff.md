# 阶段6：条件可信来源下的登录退避（实现与验证）

基线main `99357d89e8ec423281c50a0b2be7b6ee82823e13`。本PR仅登录限流，不含前端组件重构、分支保护、部署、数据库结构或凭据变更。

## 平台核查与启用边界

本轮只读再次确认生产为Sites v7、环境revision4，未设置TRUST_CF_CONNECTING_IP；Sites元信息/已有技能资料没有给出覆盖自定义域名、原生地址、Worker转发/直达路径的IP净化防伪契约。Cloudflare的通用品牌/请求头说明和合成请求均不能证明本站入口可信。生产开关保持关闭，不执行攻击性线上测试，不新增凭据。

## 最小实现方案

- 仅显式信任标志为字符串1且cf-connecting-ip是合法可规范化IP时，运行新退避路径；不会改信任条件或相信X-Forwarded-For。
- 非可信、缺失/非法IP仍走原shared-unverified-edge共享来源与用户名硬限流：10次/15分钟、总量100，保持现有安全降级，不声称跨客户端隔离，也不掩盖管理员仍可能被共享桶锁住的限制。
- 可信来源保留每IP15分钟100次总尝试上限；按规范IP+用户名的独立失败桶在真实密码验证失败后计数。采用新失败桶命名空间，避免把旧“总尝试/窗口起点”记录误解释为“失败数/最后失败时刻”。只复用现有bucket/attempts/window_start三字段，不改schema。
- 首4次错误密码401，第5次失败后429/Retry-After2秒，随后4/8/16…上限900秒。等待期请求不再执行密码哈希、不增加失败数或延长失败时刻，但仍计IP总尝试。成功登录仅在原安全提交成功时清本对失败桶；15分钟无真实失败后允许重置。
- scrypt/未知用户dummy哈希、Origin/CSRF/会话/CAS/安全日志与错误JSON保持。旧非登录429和安全降级429仍900秒；新路径只提供受控1～900的Retry-After，不增加错误JSON字段或泄露IP/用户名。
- 所有“可信IP”测试只模拟已被证明可信的配置条件；代码实现及50攻击IP/管理员隔离通过不能替代真实平台防伪证据，阶段6线上启用仍未完成。

## 算法、计数与兼容边界

失败桶window_start在新命名空间表示最后一次实际验证失败时间，旧命名空间含义不变。冷却检查在scrypt前执行；只有通过冷却检查且密码/dummy验证确实失败才原子UPSERT失败桶。阻止期仍消耗IP总尝试。旧IP窗口严格`window_start < now-900000`才重置；新失败桶在无失败恰好900000毫秒时重置。Retry-After取向上整秒并限制1～900；第五次失败2秒，第十四次及以后最长900秒。

并发允许若干请求在同一次冷却发布前已开始验证；原子UPSERT不丢失这些失败，后续等待以最新失败状态为准。不声称序列化所有scrypt或最多同时四次猜测。成功登录删除本失败桶与会话/audit/revision在原事务一起提交；失败不删除，其它IP/用户名的桶不清除。IP总量仍包括成功、失败及等待中的请求，保留每15分钟100次。

IPv6通过Node合法IP校验后按URL标准规范化，等价压缩/展开拼法不建立新桶。只使用cf-connecting-ip，既有显式开关仍须入口可信契约先成立。原有不可信共享来源10次硬锁原样保留，此PR不能解决未启用可信来源时的跨客户端管理员锁定。

错误JSON未增加字段/更改现有message/code；唯一有意行为是可信条件下新退避时机与Retry-After动态等待值。私有WeakMap仅保存本次新建的标准RATE_LIMITED错误元数据，不访问任意异常的retryAfter属性。其它429仍900。OpenAPI 1.1.0已有通用429和整数Retry-After说明，无需更改公开文档或asset pin；前端全部资源不变。

## 独立审查发现的二元组编码缺陷

候选9eadd4ff中的可信失败桶曾用`peer + ':' + username`哈希，合法IPv6与含冒号的未知用户名可发生组合碰撞，错误地锁另一IP管理员。新增真实D1/密码回归在该候选实际返回429、目标200；红灯保存在`login-backoff-tuple-red.log`（仅去除行尾空白，断言/值不变；原输出保留于执行工作区）。现改为`JSON.stringify([peer, username])`的无歧义二元组序列，不是降低阈值。核查其它桶：IP总量只哈希单一规范IP，旧非可信用户名桶的peer是固定常量，没有可变二元组歧义，旧降级原样保留。新命名空间尚未部署/启用，不移动生产记录或改schema。

## 在途并发与可用性边界

本方案阻断已发布失败状态之后的新请求，不将未完成的密码验证串行化。多个请求可先通过预检，再陆续完成KDF；首4个实际失败返回401，之后失败返回429并继续原子累计。现有IP100次硬帽仍约束同IP窗口总量，但不是全局CPU并发上限。没有另加进程锁、schema或新凭据；不能宣称第五个请求之前最多只有4个KDF在途。

新增50个真正并发loopback HTTP请求进入workerd/D1的有界测试，记录实际完成验证数与预检拒绝数（依运行调度而异）；所有请求都有独立rid。记录原并发样本后，单独在合成D1显式建立新鲜上限冷却前提（不把该夹具状态冒充自然并发计数），确认剩余等待长于HTTP请求超时，再发请求429且该夹具桶完全不变；避免合法2秒过期造成偶发假红。另有真实D1的冷却查询计数用例证实等待期不会查询用户/进入密码验证。仅模拟平台已确认可信的配置条件，不是生产负载或来源可信度证明。

IP边界在真实D1明确锁定：900000毫秒仍429/Retry-After1，900001毫秒放行并重置；新失败桶900000毫秒无真实失败则复位。这是保留既有总量`<`与新失败窗口`<=`两种定义，没有为一致形式悄悄改变旧硬帽。

前候选9eadd4ff本地全量253/253及其精确CI曾通过，但不覆盖后来发现的二元组碰撞；该结果不能替代修补后的最终完整CI。碰撞修补后全量验收以新head为准，绝不称旧绿灯已证明安全隔离。
