## 最小实现方案

- 仅显式信任标志为字符串1且cf-connecting-ip是合法可规范化IP时，运行新退避路径；不会改信任条件或相信X-Forwarded-For。
- 非可信、缺失/非法IP仍走原shared-unverified-edge共享来源与用户名硬限流：10次/15分钟、总量100，保持现有安全降级，不声称跨客户端隔离，也不掩盖管理员仍可能被共享桶锁住的限制。
- 可信来源保留每IP15分钟100次总尝试上限；按规范IP+用户名的独立失败桶在真实密码验证失败后计数。采用新失败桶命名空间，避免把旧“总尝试/窗口起点”记录误解释为“失败数/最后失败时刻”。只复用现有bucket/attempts/window_start三字段，不改schema。
- 首4次错误密码401，第5次失败后429/Retry-After2秒，随后4/8/16…上限900秒。等待期请求不再执行密码哈希、不增加失败数或延长失败时刻，但仍计IP总尝试。成功登录仅在原安全提交成功时清本对失败桶；15分钟无真实失败后允许重置。
- scrypt/未知用户dummy哈希、Origin/CSRF/会话/CAS/安全日志与错误JSON保持。旧非登录429和安全降级429仍900秒；新路径只提供受控1～900的Retry-After，不增加错误JSON字段或泄露IP/用户名。
- 所有“可信IP”测试只模拟已被证明可信的配置条件；代码实现及50攻击IP/管理员隔离通过不能替代真实平台防伪证据，阶段6线上启用仍未完成。
