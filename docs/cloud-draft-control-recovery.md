# 云端草稿控制故障与等待恢复

此流程用于 dot 云电脑，不调用用户本机的 Python 草稿助手。网站负责保存 Word、通知、认领及投递账本；真正的标签页和文档导入操作发生在执行者的官方 Cua 会话中。

## 控制检查先于文件提交

先用受支持的浏览器工具读取当前平台标签页，确认目标账号并核对已有草稿。若工具在读取页面前报凭据状态无法恢复、连接中断或无法控制标签页，停止文件提交，保留最终 Word 和已知草稿 URL。这是执行环境故障，不能写成头条导入失败或风控。没有 attempt 仅表示网站没有记录到尝试，不证明历史上从未提交。

当前执行工具没有可调用的 dot 云浏览器重启接口。通过 dot 的正规云电脑界面处理运行环境问题；若用户正在接管，需由用户归还控制。不得通过清除凭据、修改安全设置或私接浏览器调试协议恢复。另一台电脑能打开平台不证明云端连接可用。

文件选择器尚未取得、没有 reserve/consume 或其他已返回的提交许可时，原标签页连接超时可以做一次有界的正常检查：读取当前同一 browser 的官方标签页清单；清单可读时，用该 browser 新建一个授权平台主页标签页。新页若可控，重新核对账号及现有草稿，建立新空白私人编辑页，加载匹配执行器并重新取得新鲜文件/页面证据，再走原授权流程。保留旧标签页和已知草稿；不重新选择浏览器、不迁移选择器或许可、不清除历史。清单或新页也失败时停止相同超时重试。

本次真实云端检查中，旧头条标签页 attach 超时并且同页恢复无效，当前浏览器的标签页清单和新建主页却都可读，目标账号已重新核对。这是执行者报告的实际控制恢复证据，尚不能代替文件提交和独立草稿验收。已 reserve/consume 的情况仍须核对同一尝试，不能把新页可控当成重导授权。

## 本次执行器修复

以前保存提示稍晚出现，会将 import_pending 写入永久 blocked，后续观察也被拒绝。现在保存提示不存在、隐藏或仍在保存时返回 waiting/import_pending；图片已经存在但尚未加载、独立编辑器未挂载或正文完全空白时，同样保留只读等待。非空正文差异、账号不符、明确平台拒绝、图注、图片身份和顺序不符仍然拒绝验收。

等待阶段仍销毁内存导入许可，禁止封面上传、文档重传和正文修改。后续由执行者再次调用 observe/verify 核对同一稿；独立回读页复用同一标签页，不再次退出或导航。需要触发已有图片的懒加载时，可在已核对身份的 reopenedTab 上调用现有 loadImages。每次调用有界，没有新增后台轮询或自动重传；多次观察仍不就绪，应报告具体阶段并保留结果。

此补丁没有把账号控件延迟挂载、部分正文或图片节点尚未出现、知乎封面未加载等情况都自动解释成等待，也没有修复云浏览器凭据恢复故障。

## 正常采用新版源码

通过已授权源码读取取得 scripts/browser-upload/cua-draft-runner.mjs，按 browser-upload-runner.md 使用 emit-cua-module.mjs 输出完整定义，并在受支持的官方 Cua 工具会话中加载。创建新的 runtime；已有尝试只能使用真实 checkpoint 只读恢复，不能迁移旧 grant 或重用消费许可。

网站部署不会更新已有 dot REPL 的函数闭包。read_article_handoff 的 browser_preflight 返回上述检查和边界，但不授予认领、提交或重传权限。本补丁通过模拟浏览器和真实 SQLite 离线集成检查；不能据此声称真实云电脑已恢复或任何文章已进头条草稿箱。

## 旧稿没有尝试账本时

云浏览器恢复后，旧人工稿仍可能是 attempt:null，既无法提供已消费的父尝试，也无法证明从未提交。本人已经明确允许可能重复的私人草稿时，使用 owner_confirmed_legacy_reimport 单次根许可，详见 owner-confirmed-reimport.md。它保存旧历史未知及已有草稿地址，绑定准确文章、平台账号、原 Word、授权消息和实际停止声明；不补造 consumed 历史，不改成 never_attempted，也不自动重传。

先加载与服务端匹配的新版 runner/bridge，保留下载好的 Word，重新获取新鲜页面和文件证据。已有消费许可、选择器或 checkpoint 均不能迁移。只有新的 consume 返回 execute_import=true 后，当前执行者才能提交文件一次，随后独立重开核验。此次授权仅用于原稿私人草稿，不公开发布。
