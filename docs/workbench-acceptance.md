# 好多鱼工作台：8 项验收修复

生产基线：`9c9fb40c10ab9f9cb2fbb0ed87beeccc5bae6108`。分支：`opt/workbench-ui-acceptance`。

本次仅修改前端必要交互、文案和样式；保留匿名 notes / memos 新增、编辑、可恢复删除，保留 snapshot、18 表、v7 与全部原数据模型。`src/`、`db/`、`drizzle/`、`shared/`、运行配置、依赖和扫描规则相对生产均无改动；仅为另一并行分支的公开 OpenAPI 校验值补充一个精确历史扫描指纹豁免（见 workbench-secret-scan-evidence.json）。没有清除浏览器数据或服务端数据。

Library 的 8 张反馈图读取只返回引用，未在本环境取得像素；使用父级逐张看图后的精确定位，并在真实本地页面复现。用户原图及正文未加入仓库，以下截图全部来自临时 D1 合成夹具。

| 验收项 | 修复与实际证据 |
| --- | --- |
| 1 备忘录二级结构、＋直接创建 | 去掉独立中间列表栏，左侧同一目录树包含分组 → 笔记，右侧编辑。手机只有目录 / 编辑两种展示。＋立即创建并聚焦标题，无添加确认。延迟初次写入时可继续编辑，迟到响应不会夺取正文焦点或光标。 |
| 2 待办历史 / 常用返回 | 历史和常用拆成两个入口及独立视图；均有“返回今日待办”。URL 的 `todo_panel` 保留视图，日期切换不丢返回入口。1440、900、375、390 均实测返回、Escape、浏览器后退和前进。 |
| 3 左下设置错位 | 侧栏导航设置 `min-height:0` 和独立滚动，品牌 / 底部不参与压缩。真实生产基线在 1440×500 时 footer bottom=610、sidebar bottom=473，确实越框；修复后 footer bottom=451、sidebar bottom=473。 |
| 4 回收站进设置，去冗余按钮 | 备忘录页头移除刷新 / 回收站 / 本机草稿三大按钮。设置提供回收站和低调的“找回未保存内容”；恢复逻辑和草稿数据仍在。实测设置进入回收站并返回。常态编辑不再显示闪现的当前草稿横幅，失败 / 冲突 / 离线草稿提示保留。 |
| 5 名称与菜单 | 网站、登录页及品牌改“好多鱼工作台”；总览 / 文章 / 数据归入可展开的“好多鱼图文”。待办 / 碎碎念 / 备忘录仍一级可达，默认首页仍待办。手机底栏为五个主入口。 |
| 6 KPI 信息图标异常 | 精确定位为“数据覆盖”右侧信息按钮。原 44×44 CSS 像素圆形背景改为 24×24 内联布局、16px SVG；扩展伪元素保留 44px 点击区。四种宽度均验证尺寸及点击后的说明弹层。 |
| 7 设置越框 | 与第 3 项同修真实尺寸 / 布局问题，不靠提高 z-index。900×600、1440×500 及手机无文档横向溢出，底部位于侧栏与外框内。 |
| 8 保存频闪、输入和失败保护 | 待办新增即时显示待添加行，按钮不再变“保存中”，输入可继续写下一条。仅超过 900ms 显示一处轻量同步提示。失败保留新草稿及原请求，手动重试复用完全相同请求。memo / notes 稳定显示“自动保存”模式，真实离线 / 未知结果 / CAS 冲突仍显示；长文 IME 期间的旧响应不覆盖文字或光标，compositionend 才继续保存。 |

## 验证

- `tests/browser-workbench-acceptance.py`：20 项通过，30 张截图，0 JS 异常、0 外部请求；真实本地 Worker + 临时 D1。
- `tests/browser-workbench-notes.py`：5 项通过，包含匿名可写、长文 IME、延迟响应、服务器内容核对及短屏 footer。
- 最终定向 Node 检查 133 项：首次 132 通过，唯一失败为旧模块计数 49；按两个准确新增模块修正后，失败项定向重验通过。未重跑无关后端全套。
- 可读模块样式检查通过：51 个模块，行长 / 函数长度限制全部满足。
- 前端 bundle 与源码一致，11 项公共资源哈希及实际 Worker 嵌入检查通过。
- 历史冻结测试通过一个基于生产 9c9 的准确 SHA-256 前端变更清单识别本轮授权变化；其余模块和后端仍严格核对。附加声明或改变既有业务仍会被拒绝。

首次执行前运行 `npm run build`；两个 Python 脚本会自行启动并关闭本地测试服务。原始结果位于被忽略的 `artifacts/workbench-acceptance/`。完整 CI 状态以交付说明和远端 run 为准，不在此预先宣称成功。
