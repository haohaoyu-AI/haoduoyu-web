# 离线快照读取边界

自动离线同步仅保存北京时间今天及之前 59 天。更早日期通过同步面板中的日期选择器明确下载，一次仅一天。范围外服务端数据、本机已有记录、离线编辑、冲突和待提交队列均保留；近期完成不代表全历史完整。

新客户端使用 `GET /workbench-snapshot?window=recent&version=2`，历史单日使用 `window=date&date=YYYY-MM-DD&version=2`。一次响应包含限定范围的 index 和各集合记录，不再按每个日期反复重建全量 manifest。全局未排期待办、标签和备忘录仍完整包含。响应的 `complete` 只适用于显式 coverage，不授予 API 编辑权限。

旧 workbench index 和缺少 window 的逐日协议在任何 D1 读取前返回 426，提示更新页面。旧 SW 或旧 tab 无须先更新即可被服务端阻止新的历史扫描；已经在旧 Worker 中执行的在途请求无法撤回。`/workbench-snapshot/scope` 及其他业务接口保持原有权限规则。

日期查询在 SQL 内限定归属和日期，并使用既有日期索引顺序，一次有界读取每个源表。没有数据库结构或数据修改。每次读取均重新验证身份和全局 revision，窗口最多两轮一致性尝试；缓存按 DB 对象、身份范围、日期范围、版本和 revision 隔离，并合并同时构建。缓存最多 4 项、8 MiB、60 秒；同 scope 每个 isolate 每分钟最多 3 次冷构建，失败构建也计数。

客户端自动读取间隔 15 分钟，另有跨 tab 的本地读取租约和持久节流；失败退避从 5 分钟逐步延长至 1 小时。身份读取失败同样阻止待提交队列定时器的快速重试。单日主动下载尊重租约、失败退避和服务端冷构建限流。

缓存证明使用独立限定范围元数据，旧完整证明迁入 archive。只在已证明的具体日期或全局未排期集合中使用相应证明，不伪造全历史或跨范围月份完整性。范围中缺失的旧实体可能已移到另一日期，因此保留实体正文，仅记录当前范围排除证明；后续 API 更新或本地编辑不会被旧排除证明隐藏。

缓存和冷构建准入是单 isolate 的最佳努力保护，不是全账户硬配额。权限核验仍可能查询公开账号的审计记录；本地测试证明查询形状、源表投影次数和数据边界，不代表已测得生产 rows_read。其他业务读取、冷 isolate 和用户主动下载仍消耗额度。本次不升级付费，也不在生产运行同步或负载测试。
