# 显式公开业务模式（待测试站验收，未发布正式站）

用户已明确同意任何互联网访客免登录查看、新增、修改和删除正式站的真实待办及自媒体业务数据。本增量将该授权实现为可关闭的业务模式，不更换认证，不删除原认证中间件，也不合并用户数据。关闭模式只恢复访问规则，不撤销已公开副本或回退已经发生的业务改删。

## 权限与数据边界

- 默认继续原登录模式；PUBLIC_BUSINESS_MODE 必须精确为字符串 1 才启用公开模式。
- PUBLIC_BUSINESS_USER_ID 必须指定经过数据归属核验的既有用户 UUID，仅该用户的待办、模板、关联和完成偏好进入公开工作台。绝不默认选第一个用户、不自动创建用户、不把其他用户的数据搬到该用户。
- PUBLIC_BUSINESS_ACCOUNT_IDS 必须是经过确认的 JSON 账号 ID 数组，最多 50 个，允许显式空数组。仅这些既有自媒体账号进入公开范围；DB 中存在其他账号不会自动公开。
- 匿名新建的运营账号通过服务端公开审计身份归入同一个公开业务空间。账号被公开操作删除后，在其删除回执保留期间从该空间排除。私人管理操作新建的账号不会自动加入。
- 数据库的自媒体业务没有按登录用户的 owner 列，不能从“只有个人使用”、用户数量或账号名称推断归属。**正式启用前必须核实备份中的用户与账号归属，并得到明确范围；本次没有读取生产库，尚未填入任何真实公开范围。** 无配置、错误用户、未知账号均拒绝公开业务请求。

匿名可使用现有账号、文章、快照、每日指标、总览、待办、模板和偏好接口。仅公开授权范围的业务 CSV；不是原始数据库备份。公开 /auth/me 仅返回固定的公开工作台标识、显示名称和 publicBusiness=true，不返回用户 ID、用户名、密码/哈希、会话 Cookie、登录令牌、密钥或 CSRF 登录能力。

有效的原 Cookie 或 Bearer 请求继续使用原用户身份和账号权限，不被重新绑定到公开用户；只读 token 仍不能写入，其他登录用户的私人待办不会被移入公开空间。有效登录者继续看原管理工作台，匿名访客看公开工作台。过期 Cookie 不强迫匿名访客登录，但新的匿名写入必须显式携带公开写请求头；已有程序不会仅凭旧 Cookie 或旧 CSRF 头意外把私人内容写入公开用户。

密码修改、密钥签发/查询/撤销、审计、安全配置和原始 /backup 等端点仍要求原认证和管理员校验。初始化端点继续其原独立秘密与一次性初始化规则。认证登录仍保留；公开模式下管理 API 可用既有管理员凭据访问，但不会在匿名 UI 中提供安全、密钥、日志或退出入口。业务详情的原用户/密钥来源标识及凭据名称会在公开响应中替换成匿名业务编辑说明；正常认证模式的原详情不变。

## 写入、删除与额度

公开写入不需要密码、Cookie 或 Bearer，但必须同时具备：

1. Origin 与配置的 SITE_ORIGIN 精确相同；
2. X-Public-Business: 1 自定义请求头；
3. 原业务要求的 JSON 类型、字段、版本/幂等及输入校验。

不返回跨来源 CORS 授权；外站浏览器无法通过自定义头的预检并借用户浏览器执行写入。服务器端 AI 可直接按该协议操作。该措施不是匿名身份认证，也不能阻止获明确授权的任何访客故意改删公开数据。

公开请求体通过流读取限制为 16KB，超过即拒绝。每个 isolate 内有有界聚合计数：每分钟最多 60 个公开 API 请求、20 个写请求，每 UTC 日最多 1000 个请求，最多保留 32 个配置桶。不信任 CF-Connecting-IP 或 X-Forwarded-For 来增加额度。计数是无额外存储费用的最佳努力保护，会随 isolate 重启而重置，也不是跨地域的分布式额度或 DDoS 防线；Cloudflare Free 的原生配额仍是最终硬限制，不自动升级付费。

待办及模板沿用原增改删、恢复、CAS 和 UUID 重试逻辑。公开模式新增以下删除接口，仅在该模式下开放：

| 接口 | 必需 JSON | 行为 |
| --- | --- | --- |
| DELETE /articles/{id} | 当前 version | 原子删除该文章及关联快照、文章每日指标，写入审计 |
| DELETE /observations/{id} | 当前 created_at | 删除授权账号文章的该快照 |
| DELETE /daily-metrics/{id} | 当前 updated_at | 删除授权账号的该每日指标 |
| DELETE /accounts/{id} | 与 URL 相同的 id | 仅删除没有文章及每日指标的账号；非空账号拒绝，仍可用原停用操作 |

删除绑定服务端白名单表名和账号范围，不能指定表名或用户。旧版本/时间标识被拒绝；成功删除保留公开审计回执，相同请求重试不重复写入。审计失败时整个删除批次及其关联行回滚。自媒体删除是永久业务删除，不新增通用回收站；正式启用前必须有可恢复的私有完整备份。原认证模式不新增这些删除能力，原 API 和 schema 保持原样。

## 构建、验收及回退

Cloudflare 构建仅在显式提供这三个公开模式配置时写入对应 vars，默认不启用。配置只进入忽略的 dist 构建目录，不会作为站点静态资源提供；不要把真实配置和备份提交到 Git。platform 构建和原认证模式均保留，既有四份迁移和 15 张表不变；无需新增依赖或云资源。

当前改动仅作为 PR36 的独立增量提交。没有迁移生产数据、改变 DNS/WAF、替换测试站浏览器线程或发布正式站。

上线顺序：私有全用户备份及 15 表完整性核验 → 私下核实待办所属用户和公开账号 ID → 协调现有测试站，以合成数据验收匿名完整 CRUD、跨用户/账号隔离、全部敏感端点、CSRF、删除回滚、限额及实际电脑/手机无 VPN 的 UI/接口体验 → 再提出精确版本和真实范围的正式启用计划。测试站的 Ego/UI 超时、免费 CPU 和长期连通性问题不由本地测试代替结论。

回退时关闭 PUBLIC_BUSINESS_MODE，并等待在途旧请求结束，恢复原登录入口和 Cookie/CSRF/Bearer 规则；数据及凭据不会自动重置。公开期间新增和修改的数据仍在，删除的数据需要按获批恢复方案处理。不得用旧库直接覆盖新写入，亦不把关闭公开模式表述为收回外界已复制的内容。
