# Windows 第四阶段：可审阅的加密历史归档

沿用独立分支 `desktop/native-workbench-20261104`。前一已测源为 0.3.1 `c46d858`，交接源为 `821644b`。本阶段只增加一项有明确收益且可在云端验证的能力：把频繁离线编辑产生的旧、从未发出、已被替代历史移入当前身份的独立加密档案，减小 32MiB 活动工作区压力。不是磁盘清理；档案与备份保留，磁盘总占用可能增加。

## 自动更新的判断

现有 Windows 工作流只有只读权限，打包脚本明确 `signed=false`、`unsigned_portable_candidate`，未签名、未安装、未正式分发；Actions artifact 只保留三天。没有已验证的 Windows 签名信任根、稳定发布清单、版本/撤回契约，因此不接入自动下载或执行更新，不将包 SHA256 冒充发布者签名。此前 artifact 下载 403 不重试，不换路线。

## 归档规则与保留边界

仅候选：旧 Superseded，真实 SendAttempts=0、无 PreparedBody、无 RemoteJson、无确认或恢复标记。保留每个资源最新记录，以及从全部保留根沿依赖、真实版本来源和替换关系的完整闭包。预算保留节点也参与闭包。未决、Confirmed、已尝试、恢复记录不归档，不移走草稿或业务缓存。

用户先预览具体候选，再确认；引擎持状态锁重算版本、ID、精确编码字节和理由。先写加密档案、刷新到盘并完整读回逐字段验证，再一次原子提交活动状态和归档 ID 索引。任何档案/读回/主状态失败都不提前移除活动原文；主状态提交失败可留下安全的未登记档案，只读发现，不自动删除或重放。归档操作 ID 持久禁止复用，原请求字符串、元数据和依赖保持。

首次归档把工作区升级至 Schema2，新版读 1/2；旧版会停止读取/写入新格式，不能静默丢掉归档索引。Schema1 不允许带新索引；正常保存禁止把现有有效 2 写回 1。显式恢复旧 Schema1 备份仍可保留完整旧原文和 Schema2 主原件，独立档案不删除。独立档案本身的 schema 为 1，使用不同 `HDYHIST1` 头。

每批默认 500、最多 1000 条/4MiB 精确编码历史；单加密档案 8MiB 上限，目录扫描 1000 项/64MiB，超限明确“扫描未完成”。有限扫描不能证明其他文件缺失：已登记项仍可单独打开，也可填写规范 UUID 在当前身份目录只读核验未登记档案，不接收任意路径。损坏、未知或缺失档案保留并报错，不重建空档或解除 ID 围栏。同一 Windows 用户 DPAPI、完整密文 SHA256、scope 和 ID 校验；不是跨用户/跨电脑可解密备份。完整私有备份应包含整个身份目录和 history 子目录。

## 剩余范围

本能力只处理可证明从未发送的旧替代历史；不会缩减已确认记录、大正文未决请求或必须保留的依赖，活动 32MiB/服务快照预算仍有效。已归档正文不参与活动检索，可从“历史档案”只读查看或导出。自动整理/确认历史归档、自动更新、正式签名与旧客户端迁移仍未实现或未核实。
