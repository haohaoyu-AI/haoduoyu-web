## 第二期阶段 3 C5：总览缓存，待独立验收

- 保持完整总览响应与全部业务口径，通过 DB/revision/query/完整授权身份隔离缓存；每次继续鉴权和首尾一致性核验。
- 用精确日界、待复盘到期和保险发布时间失效，时钟倒退保守 miss，重试重新采样；不采用近似 TTL。
- 16 MiB 总预算、15 MiB 单项、50 项上限，并预留每个活跃租约的临时缓冲；失败与被弃尝试不发布，取消/异步读取结束后释放。
- 超大或预算不足时完整返回原响应，不缩减字段、历史、正文或窗口；没有新接口、数据库迁移、前端依赖或 UI 改动。
- 增加旧新版完整响应、错误优先级、跨界、作用域、C2 失败、五轮冲突、取消及读取失败回归，以及同场大数据基准和本地 workerd 诊断工具。
- 新增流表示的明确边界：返回响应后正文读取故障只能拒绝读取，不能改写为 JSON 500；故障项会退役。逻辑缓存预算和 Inspector 采样不等于完整生产 isolate 内存上限证明。

准确测试、原始样本、性能和限制见 [C5 验证](overview-cache-validation.md) 与 [性能记录](perf-baseline.md)。
