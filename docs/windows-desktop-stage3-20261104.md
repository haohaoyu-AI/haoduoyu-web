## 恢复安全阶段

发现并修复旧备份的时间线歧义：备份中的未决请求，可能已经在较新的主文件期间发送、重试或确认。原来的恢复仅把 InFlight 转为 Unknown，不足以证明旧 Queued/Blocked 等从未发出。现在显式回退恢复会在原子安装前，将所有恢复的非终态持久标为 Unknown 并记录来源，禁止直接重排，保留原 ID、正文、实际冻结正文、真实尝试次数、依赖和既有响应。Confirmed/Superseded 不复活。损坏主文件和备份原件保留，保护失败、取消或坏备份不替换主文件。

恢复时对已有草稿持久标记来源，后续自动保存和重开不能洗掉标记。服务端分配文章 ID 的旧新建稿可能缺失较新回执，因此禁止从该稿再次 POST 创建；仍可继续本机编辑、导出，并从台账核对后打开真实服务器记录继续受版本保护的更新。稳定 UUID 的其他资料继续遵循原版本/hash 检查；fresh 新稿不受旧恢复来源影响。

Core 最初 70/70（7 组恢复）通过，随后把旧 Blocked/Conflict 的时间线歧义一并补齐：这些请求可能在备份后被人工重试并确认。恢复现对所有非终态统一 Unknown，并持久标记请求恢复来源，禁止直接 RetryUnchanged，保留精确回执确认及显式历史处理。**最新 Core 71/71，恢复 8/8** 已在本地及上述正常 Windows 检查通过；正常未恢复 Unknown 的既有契约保持。新增真实旧 Blocked → 较新 Confirmed 主文件损坏 → 回退恢复 → 重开/直接重试均零发送的回归。
