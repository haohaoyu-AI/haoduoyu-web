## 恢复安全阶段

发现并修复旧备份的时间线歧义：备份中的 Queued 请求，可能已经在较新的主文件期间发送或确认。原来的恢复仅把 InFlight 转为 Unknown，不足以证明旧 Queued 从未发出。现在显式回退恢复会在原子安装前，将恢复的 Queued/InFlight 持久标为 Unknown，保留原 ID、正文、实际冻结正文、真实尝试次数、依赖和既有响应；不会自动重发。Confirmed/Superseded 不复活。损坏主文件和备份原件保留，保护失败、取消或坏备份不替换主文件。

恢复时对已有草稿持久标记来源，后续自动保存和重开不能洗掉标记。服务端分配文章 ID 的旧新建稿可能缺失较新回执，因此禁止从该稿再次 POST 创建；仍可继续本机编辑、导出，并从台账核对后打开真实服务器记录继续受版本保护的更新。稳定 UUID 的其他资料继续遵循原版本/hash 检查；fresh 新稿不受旧恢复来源影响。

Core **70/70**（新增 7 组实际临时加密文件恢复检查）通过。原生 Windows 测试增加 1 组实际显示恢复链：私有 B → 配置备份中的私有 A → A 的业务备份恢复 → 未决请求围栏 → 旧新建文章禁止重复创建 → A 中文续编并关开。检查 B 原件、配置损坏原件和业务备份原字节均保留，零 HTTP/socket。共 **29 个顶层测试、16 组显示窗口流程**，完整 Release 跨编译零警告/零错误；**本阶段尚待独立源提交的正常 Windows CI 实际执行**。

候选版本升为 0.3.0，格式仍兼容 schema 1 的旧文件；新恢复标记缺失时默认为未恢复。不存在从旧 Windows 客户端自动迁移的操作。

## 接续中的本机检索

正在实现当前身份分区内跨模块的只读检索，区分缓存、草稿、原请求、实际冻结请求和远端证据，不把未确认请求称为服务端保存，也不把缓存摘要称为完整正文。不联网、不跨历史目录或其他账号检索，保留预算、取消与局部覆盖提示。该功能在完整接入并测试前不计为已完成。

现本机检索已完成原生导航/Ctrl+F、中文多词查询、分页、来源/状态和工作生活分类、只读预览/导出、回原模块与原 key 草稿续编。查询和结果在切身份后清空，结果不直接作为服务器写入实体。独立检索 **35/35** 合成检查通过，包括来源去重、Unknown 多份证据、Unicode、零/null、预算/取消、外分区与凭据来源排除及不突变。显式局部结果中的数量只是当前扫描数量，不作为严格下界或服务端总量。

新增一组实际显示窗口检索隔离/续编流程，现 **30 个 Windows 顶层测试、17 组显示窗口流程**。恢复检查点 `f4e10fc` 的正常 CI `41894595933` 已执行，Windows 28/29，新增测试把真实导航名“本机与恢复”误写为“本机恢复”，尚未进入恢复主体；两处字面量已修，全部恢复断言保留。当前整合已跨编译，新的 30 项与完整恢复链仍须新提交的实际 Windows CI。
