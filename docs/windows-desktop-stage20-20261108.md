## 实际缺口与读取合同

此前一键“准备离线资料”只读取活动常用事项；归档虽有原生页面，断网前仍须另去该页手动读取。现将活动及归档两张完整列表纳入同一有界、只读准备批次，不新增服务端写接口。

固定34bff302的GET /api/v1/todo-templates及?archived=1分别返回当前身份完整列表、无分页；归档写经mutate推进全局revision。沿用已有revision、scope和日期首尾核对，另外将两列表末尾再读并比较data；本机读取时间不参与比较，不将第二次读取重复计入实体数。归档不加入原business snapshot的manifest/hash，不因活动列表缺席推断归档为空。

## 完整性、来源及界面

两条精确查询键分别保存完整标记、原始来源、UTC读取时间、本机cacheScopeId和服务scope；本机分区与服务scope明确分开，调用必须显式提供本机分区。保留严格网络解析，新本机缓存解析入口仅接受合法完整标记，不让带本机投影标记的网络响应冒充来源。归档页与投影统一用本机入口，避免能投影但看不到来源时间。

活动/归档各首读、末读，不区分UUID大小写跨表查重；两表合计10000项，单网络响应1MiB、缓存24MiB、50000行和10000请求及既有wire预算不扩大。失败、取消、超限、错范围、资料/revision/scope/日期变化均整批停止，原缓存、草稿和未确认请求不变；成功才一次CacheBatch。落盘仍在线程池执行，UI核对原engine/store、身份、本机/服务scope及取消，迟到结果不用于另一工作区。

首尾核对只是准备期间变化检测，不承诺跨请求事务、消除ABA或外部owner配置竞态。读取相同当前列表不是未知写请求的收据，不自动确认、重排或重发Unknown；归档/恢复请求的原围栏不变。固定候选合同不等于生产精确Worker、迁移状态或真实账号验收。
