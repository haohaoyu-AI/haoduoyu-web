# Independent editorial contract v2

The normal authenticated page `/writing/editorial-run` starts one bounded request and shows genuine progress/frozen text; it requires no JSON, actor IDs or per-stage settings. `/writing/editorial-helper` is the assistant-only execution workbench. `/api/writing/editorial-flow` and the named MCP tools use the same owner-bound service. Paid execution uses `/api/claude/editorial-run` with the existing NDJSON heartbeat transport and the existing SSE-aware Claude provider adapter. No new provider, arbitrary endpoint, secret store or automatic schedule is introduced. The additive `editorial.requested` event is separate from existing topic/article subscriptions; its real trigger must be explicitly created and verified before background execution is claimed.

## Sequence and artifacts

1. Select a topic, angle and style requirements. Freeze a public fact pack with distinct source IDs, public URLs, publication dates, event dates, access dates and source context. Each fact maps to actual source IDs. Freeze the complete current V2.2 writing prompt and the separate complete three fixed style/prose/format parts. Examples remain style references, never evidence for the new article.
2. The frozen Claude writer produces an outline with source/fact mappings and honest blocking fact gaps. A distinct outline reviewer checks the exact outline projection and records anchored issues. A blocking gap or non-pass review prevents the body call.
3. The same Claude writer produces title plus complete body. An independent structure reviewer checks logic, progression and expression. Every issue has an original exact quote/location, type, severity, basis and revision goal. Fact concerns here are hints for the separate full fact check.
4. If necessary, the same Claude writer revises the complete article, returning an adoption/rejection decision for every issue and exact before/after positional change records. Each changed, inserted or deleted position is accounted for. If the review has zero issues, an explicit skip retains the identical article/hash and creates no paid request.
5. A distinct fact checker independently checks the title and entire revised body. Coverage entries must concatenate exactly to every complete title/paragraph, with no gaps, duplicates or overlap. They distinguish facts, opinions and metaphors. Confirmed facts require frozen source IDs, corresponding exact source publication/event dates, and substantive temporal context. Quote existence alone does not establish correct speaker/time/context. Unconfirmed claims and contradictions remain explicit.
6. If necessary, the same Claude writer fixes the fact report, with the same full revision audit. A fully passed zero-issue fact report permits explicit identical-hash retention without another paid request.
7. A distinct final verifier reads the actual clean final title and full text, including all changes and newly introduced facts. Complete coverage and all paragraph/name/number/metaphor/quote-time-context checks are mandatory. Diff-only checks, incomplete coverage, unresolved facts, remaining issues or `passed:false` cannot freeze an article.
8. Freeze the exact independently verified article/hash. The final artifact preserves all versions, reports, actor/execution/model labels, provenance and original provider receipt references. Dispatch the same original article ID through the existing illustration/Word/private-draft event. No public publishing.

Five pairwise-distinct participant actor IDs are required; the Claude writer is constant across all necessary writing/revision stages. Independent result receipts are owner-attested execution records, not cryptographic proof that an agent actually ran. Users/agents must record real execution IDs. A reviewer cannot supply a writer revision. Actual writer provenance is validated against the immutable actual completed Claude response, requested/returned model, exact input hash and stage receipt. A provider model label does not independently verify its upstream identity.

## Paid confirmation and recovery

There are at most four necessary Claude requests: outline, body, optional structure revision, optional fact revision. For the user-started request, one explicit bounded authorization covers only that new flow's frozen model/V2.2/output limit and its four named possible stages. Assistant execution still uses a distinct atomic stage claim, unique reservation and actual provider receipt for every necessary call. The legacy standalone helper path retains per-stage confirmations. This never grants an additional attempt after a failed/unknown stage. Extra steps are not charged just to fill a workflow.

A repeated/concurrent claim has one winner. Only that winner receives a token, held in volatile page memory. A repeated execution reads an existing reservation without a new provider call. Failed, expired and unknown requests cannot reset their reservation or silently retry. A saved completed result may be reconciled with `recover_editorial_stage`, which never contacts the provider. Losing a winning token before a request is sent leaves that claim read-only; it is not an authorization to create another paid claim.

Technical failures (including HTTP 524/model-receipt mismatch), invalid completed content, independent content blockers, and final verification failures are separate states. Full actual failed/partial provider receipts and safe numeric usage remain readable. Credential-containing content is suppressed; key/token values never enter prompts, UI state, logs or artifact metadata.

Reversible archive/pause controls preserve the old generation state and all receipts. Default lists hide archived runs; owner audit reads remain available. In-flight returns retain their receipt but cannot advance an archived run. Restore never generates, recovers or dispatches; a pre-existing pause stays paused. Controls and SQL mutations are owner-scoped and guarded against read-then-archive races.

## Compatibility and implementation boundary

Migration 0015 adds only reversible workflow controls; migration 0016 adds isolated `editorial_flows` and `editorial_stages` tables. Migration 0017 adds isolated durable editorial requests and their separate wake outbox. All have official Drizzle journal/snapshots. Legacy daily/manual/rewrite/outline snapshots and quota rows are not upgraded or rewritten. The existing `article.submitted` subscription is reused without modification. The 08:00 schedule stays paused. The old outline page remains accessible for existing batch reads and authorized compatibility operations.

The user surface is a one-time start/status page. A separately verified assistant trigger claims the request and coordinates actual research and independent agents. The website cannot itself launch real agents; the assistant-only stepwise workbench remains for genuine long-connection writer execution. Research and reviews must actually run before their reports are submitted. Fact coverage validates completeness/bindings; semantic truth still depends on real independent research. A lack of verified materials stops the flow instead of padding its default 2000–3000-character body.

- `node tests/editorial-ui.mjs`: offline assistant helper interaction/SSR.
- `node tests/editorial-request.mjs` and `node tests/editorial-request-ui.mjs`: one saved bounded start, metadata-race guards, durable disconnected wake/outbox, real-claim protection, bound four-stage receipt path, cancel/old-test preservation, status-only polling, ordinary user UI and interruption/idempotency/auth tests.
- Existing outline/daily/manual/rewrite/security suites are rerun. No test requires a real paid model, production database, draft upload, or scheduled task.

No live paid acceptance, production database migration, real independent agent execution, image generation or private-draft delivery was performed during this implementation. Production rollout and paid acceptance remain separate authorized steps.
