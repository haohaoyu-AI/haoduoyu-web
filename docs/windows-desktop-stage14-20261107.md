## 实际能力与数据保护

- 待办菜单的原生备注页，显示原事项、原日期、版本、完成状态和备注来源；独立草稿kind `todo-note`、键 `/local/todo-note/{UUID}`，原待办创建稿保留。350ms自动保存、Ctrl+S、切页/关闭flush和离线重开沿用加密原子存储。首次WPF呈现不把换行显示差异当用户编辑；超长或未完成输入可存本机，不静默截断粘贴，发送前再严格校验。
- 清空本机输入与服务器保存分开；保留清空前原文及显式恢复。旧缓存缺note为未取得，须实际输入或明确清空才能排队，不能把未知当空。日历/历史只读预览、导出及本机检索纳入备注、独立稿、原请求和实际响应来源；备注不改变原事项及完成统计。
- HTTP正文不包含日期。本机请求另存TodoNoteDate，发送前核原UUID、资源键和真实日期，成功2xx确认前再严格检查完整记录、原日期、版本及精确备注。依赖创建/完成/恢复/备注回执取得真实版本后只冻结一次；不猜版本0、日期或今天。日期字段可空且旧操作不序列化空字段，工作区Schema1/2保持。
- 清空的已核验回执不会被通用merge补回旧备注；后续同版本省略字段可保留该清空证据，更高版本缺字段仍保守未知。真实条件重放允许其他端先改变完成状态，客户端采用合法当前完整回执，不强行用旧完成状态拒绝或覆盖它。
- Queue ResourceKey仍为原 `/api/v1/todos/{UUID}`，与完成、删除等共用围栏。Unknown不能凭当前相同文字确认、替换或重排；备份恢复保留原ID、字节、版本、日期与来源。Conflict及已有远端错误响应保守只读核对/导出。明确未发送且无远端响应、非恢复的Blocked，可重新登录原账号，核对原日期并明确确认后原样重排；不自动写入。
- 刷新与本机写入前后核对身份、scope、Engine、store、页面epoch和取消。坏响应、401/403/409/413、取消、预算超限或归属变化均保全原副本与未确认请求。当前日预览输入/输出8MiB、10000行、预估展开64MiB；优先按已知当日ID跳过无关详情，缺完整基线时仍有明确总预算的日期发现，不宣称完全不读其他日信息。网络原始响应仍1MiB。
