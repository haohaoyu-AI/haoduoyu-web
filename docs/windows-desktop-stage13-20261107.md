## 实际客户端改动

- 原生活动/归档标签页、详情、当前本机来源和显式读取，保留新建、改名、加入日期及原软删除含义。归档、恢复均用同一模板资源键与真实原始版本，通过持久队列发送严格正文；已有未决操作不会被改名或新动作替换。
- 两类列表分别建立完整性和删除证据范围，不互相当作删除依据；business snapshot只含活动模板，缺席不清除归档缓存。归档使用独立archived_at/本机意图，不复用deleted。既有待办的正文、完成状态、日期和关联保留；归档与未决恢复不启用模板创建新待办，旧活动缓存不能覆盖较新待办的不可用状态。
- 新回执专属校验在通用restore分支之前，严格核对UUID、完整源字段、目标归档状态及同版本/下一版本。归档恢复不要求不存在的deleted_at，不放宽其他资源校验。依赖版本仅取同资源、同身份分区的真实已确认回执，并只冻结一次；普通旧模板版本路径保持回归。
- Unknown没有模板精确保存收据。同步中心只允许两列表只读核对、原请求/响应查看和导出；列表当前相同状态不能确认某次丢失请求、解除围栏或重发。恢复的请求与归档冲突也保守保留，未宣称自动解决。尚未发送且未恢复的Queued可明确取消；原DELETE历史不转换成归档。
- 刷新前后核对身份、scope、Engine、store、epoch和取消；成对核对须两个响应都成功才单次缓存提交，但不称远端事务快照。坏成功响应、413、超预算、取消或归属变化保全旧副本、草稿、队列和请求字节。

本机预览只取相关模板与依赖；输入总量8MiB/10000行，受控预估展开总量64MiB，最终JSON8MiB；网络每个原始响应仍1MiB。超限整体停止，不静默截断。源统计窗口及习惯判断保留，未知合法metadata与中文Unicode原文保留。
