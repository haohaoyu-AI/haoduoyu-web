## 修正的问题

既有WorkspaceProjection已计算 `_local_active_note_count`，但分组列表和软删除确认只显示旧服务端 `active_note_count`。本机新增、取消笔记后，原生列表可能显示旧篇数，或在缺字段时留下不明确的空计数。本轮0.17.0不改投影、后端、业务统计、版本或任何写合同，只让列表和分组详情明确分开显示“本机已知活动数”与“服务端副本活动数”。局部已知不是全库存，真实零保留为0，未取得及无效类型不补0。

批量软删除仍保留原组ID、版本、标题、save_id及真正的服务端副本计数。缺少可核实的服务端数时，在Win32确认框和排队之前停止，不用本机数替代，也不生成猜测的0。服务端仍会重新核对标题、版本和活动数，其他设备或本机未决变化可能导致拒绝，不冒充实时一致快照。尚未发送的新分组单独走原取消创建逻辑，不要求不存在的服务端数；子稿、子请求及依赖围栏仍保留，不转换成远端DELETE。

已知正式合同仍禁止更改已有笔记的group_id。本轮不“移动”笔记，也不采用复制后删除或更改服务端权限来绕过该限制。
