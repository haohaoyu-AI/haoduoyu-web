## 原入口与修正

此前“本机与恢复”遍历全部目录、File.ReadAllBytes读完整密文、解密后格式化整个JSON并塞进TextBox；它没有沿用主Store的32MiB预算，也没有给目录发现或预览设置上限。本轮0.18.0新增独立只读恢复工具，不改变正常AtomicWorkspaceStore读写及schema。

清单改为显式“读取历史分区清单（只读）”，在线程池执行。发现最多检查1000个目录项，预算包含无关项，超限明确标为部分清单，不把未读分区当作不存在。只接受小写64位哈希分区，拒绝根、分区或最终文件链接/重解析点，密文和解密明文分别限32MiB；不是只查FileInfo再无界分配。实际流按已核长度读取并最多额外检查1字节，增长、缩短、取消、坏header、坏JSON、错或重复ScopeId均保留原件。

Windows使用只读句柄、OPEN_REPARSE_POINT与属性/最终路径核对；Linux使用已打开目录句柄的openat与O_NOFOLLOW。句柄只在一次发现/读取期间持有，不创建workspace.lock、目录或备份，也不导入/执行旧队列。Linux目录句柄固定已打开对象，但最终路径名核对并不等同Windows；目录发现不是跨时刻的事务快照。当前实现不宣称消除任意恶意祖先重命名竞态。Windows规范化最终路径与传入路径不一致时会保守拒绝，合法8.3别名、祖先junction及重定向AppData尚未实测，不能承诺兼容；原件不会被修改。

## 只读抢救与预览

解密后仅验证有界JSON对象及唯一匹配ScopeId，不将原件反序列化为WorkspaceState，也不调用OperationGraph。这样即使旧主Store因未知schema、坏队列或字段类型拒绝打开，用户仍可只读抢救正文；这不证明原件是可执行/可写工作区。

原始JSON的未知字段、空白、数字表达和尾部全部保留，不全量重新排版。原生TextBox最多显示256Ki字符，按CRLF最坏显示长度给单CR/LF记2单位，不从surrogate对中间截断，并明确提示“仅预览”；完整原文另经预览导出选择、确认及SaveFileDialog走已有严格原子纯文本写入。解密byte[]在finally清零，但显示/导出所需的.NET字符串不承诺立即安全擦除。

UI捕获允许为空的engine/store、身份和页面epoch，线程池返回后重新核对，不把迟到结果放到新工作区。主打开真实失败、engine/store为空时入口仍能使用。模态预览内按钮只返回选择，关闭后继续原action的导出确认，不在已占用的全局Run闸门中嵌套调用Run。
