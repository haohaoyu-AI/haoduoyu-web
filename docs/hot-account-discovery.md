## 已实现

- `/imitation` 顶部持续显示文娱对标账号池和添加按钮。初始为空，不预填未经核验的大号。本人提供名称与今日头条公开账号 URL；界面明确账号定位未核验，可移除。最多20个账号，规范化公开主页分享参数并去重。
- `hot_benchmark_accounts` 与 `hot_benchmark_scans` 在现有 D1 中持久化，所有读写按 owner 隔离。新增迁移0034只创建两张表和三个索引；保留0033及之前的迁移、快照。未应用生产迁移。
- `/api/imitation/discovery` GET读取账号和扫描；POST只提供添加、移除、刷新。保留本人认证、同源来源和专用请求头检查，无缓存。没有查询写作授权、发送订阅事件、调用模型或创建稿件。
- 刷新冻结账号池快照，带 request_key 幂等；同一 owner 正在扫描时另一新意图明确返回409 scan_busy，声明本次请求未接纳，并附当前扫描供页面继续跟踪，不重复出站采集。已接纳意图的重试始终读取原记录。扫描窗口45秒，存储租约60秒；SQL提交时用数据库时钟检查租约及后继记录，过期或被替代的旧扫描不能覆盖结果。账号增删后明确要求刷新。
- 正常公开 HTML 请求复用原采集器：仅 HTTPS 头条账号主页；匿名、无 Cookie、拒绝跳转、限时、最多1.5MB。遇登录/验证码/401/403/429即停止访问该账号；继续其他独立账号，不使用隐藏接口、登录态、脚本执行、付费采集或绕过方法。
- 保守卡片适配器使用固定版本parse5解析真实HTML语法，要求可见 main 内同一 article/li 中唯一文章URL、标题、唯一且匹配账号的显式作者链接、带时区 datetime 的绝对可见日期，以及专用统计节点。日期时间必须与可见值一致；按可见日期/分钟/秒精度的最早可能时刻核验72小时，并保存精度证据。先登记所有版本再筛选，同一URL的低阅读、过期、缺字段及无效版本冲突均排除。脚本、textarea、属性文本、正文articleBody、推荐用户名不作为文章指标或作者。歧义卡片计入未完整核验。只接受本篇阅读下界至少100000，最多返回5篇。每账号只读取一次公开主页，最多解析100张卡片；超过上限明确为不完整，不擅自访问分页或声明覆盖所有历史文章。
- 指标原始显示值如 `12万阅读`、页面/卡片SHA256、原始卡片HTML、账号/文章URL、日期和观察时间保存在扫描结果中。约数 exact 为 null，使用一个完整显示单位的保守区间覆盖常见取整方式；`12万`为110000–130000区间而非精确120000。平台取整规则尚未实测。`10万`不能证明最低100000而排除；`10万+`或精确100000可达门槛。缺点赞/评论保留 null，真实0保留0。不提取正文票房、推荐旁栏、累计账号指标或重复冲突计数。
- 发现阶段无需正文；卡片证据不等于全文核验，也不满足原写作门槛。旧 `hotReadEligibilityReason` / JSON-LD / 正文资格校验保留，旧研究和收费接口未修改。
- 文章行只显示标题、阅读、点赞、评论、查看原文；刷新按钮和账号池在顶部。区分初始加载、空账号池、扫描中、真正核验为空、网络/访问受阻、字段不可核验、部分成功、租约中断和账号池变化，不再同时显示“扫描中”和“暂无符合条件”。
