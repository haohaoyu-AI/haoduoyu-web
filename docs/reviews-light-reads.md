## 实现与接口约束

- `GET /due-reviews?account_id=` 只读取授权文章及观察节点 kind/as_of，不调用 overview，不读每日数据或计算累计、趋势。与 overview 共享纯待办函数；C5 精确失效也复用同一未完成事件表。已核实日期、同 kind 且 as_of>=due 才完成，输出及排序保持。
- `GET /articles?fields=index` 仅返回 id/title/account_id/platform/published_at，完全不查快照，保留授权、文章自身字段过滤和原分页；OpenAPI 保持1.1.0并明确新增响应 schema。
- **待审取舍**：不查快照与支持依赖快照的排序/筛选不能同时成立。新索引模式对指标/最新快照排序及 no_snapshot/zero_reads 等状态明确返回400，不静默忽略。published_at/duration、题材、date_unverified及其他原生文章字段支持。未带 fields 的旧接口保持原字段与规则；旧20错误样例、原109静态调用契约不放宽，3个新模式验证调用单列。
- 前端按会话身份和规范化完整有效查询合并索引 promise，最多十组，最小记录冻结。成功写在统一 api 路径且解析 JSON 前清理；普通写只推进索引 generation。登录初始化、登录页、认证成功及手动刷新清理会话/索引。失败删除，旧在途请求不能重新填充，渲染和弹窗使用前校验 generation 及原版本。
- 另存 reviewArticles，不覆盖文章页完整 state.articles，保留原文菜单。直接补录目标若不在缓存，强制轻量重取一次；仍不存在/不可见则拒绝打开，不默选另一篇。其他客户端写入不自动广播到本页面；刷新/重新载入可更新，直接目标缺失有上述保护。
- 独立 sessionEpoch 与请求身份在 api 的401副作用之前检查。旧401仍拒绝，但不清新身份/缓存或显示旧错误；同一用户重新登录也受保护。普通成功写不推进会话epoch，当前真实401正常退出。init拒绝旧世代异步结果。CSRF、Origin、e/safeURL及后端安全机制不变。

## 真实Cookie竞态和功能

[浏览器结果](reviews-light-races.json)保留11项逐项结果与原诊断：

1. 真实认证身份；在途旧索引收到后，成功写后的新记录仍重取并显示。
2. 在途录入后导航不重新开旧弹窗，文章原文菜单仍存在。
3. 注入一次索引503后可实际重试，不永久缓存失败。
4. 从其他客户端成功创建的直接目标若不在缓存，录入重取并选中正确id。
5. 每日账号切换选项及真实0提交；快照真实0、缺项保留。两个实际表单写成功后各重取一次索引。
6. 退出后旧200丢弃、索引清空；重新登录真实会话不复用旧索引。
7. 请求捕获旧Cookie后退出，原请求实际向Worker取回401，延迟到同一账号新登录后再交付：新身份/缓存/UI均保留。不是手工伪造认证成功。
8. 外部真实退出当前Cookie后，当前api请求实际401仍正常返回登录页、清空缓存。

竞态脚本仅在回环适配器显式开启私有模块探针，暴露实际api/index函数及只读状态访问器；认证、CSRF、写接口和表单事件均真实，没有替换生产函数或模拟登录。探针不在public源码/Worker构建中，正常截图不启用它。唯一注入故障为明确标记的503，延迟401来自真实已撤销Cookie。原始控制台401/503保留，pageerrors为0，不宣称全流程控制台零错误。
