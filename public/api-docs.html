好多鱼图文 · AI 接入

经营数据需要账号密码或独立授权凭证。此页面不包含任何经营数据。

基础路径：/api/v1。机器人使用 Authorization: Bearer <token>；写入时提供 Idempotency-Key，保存后按返回编号读回确认。

网站管理员在「AI 接入」中创建凭证，限定账号和读写权限。每次复盘保留数据时间与来源；累计快照与每日发生量分别提交。

接口

  • GET /accounts：列出授权账号
  • GET /articles：默认检索已发布文章；显式 status 选择单一生命周期状态
  • POST /articles：登记成功发布文章或保存真实草稿
  • PATCH /articles：按流水线身份键递归合并保存
  • POST /observations：追加累计复盘快照
  • POST /daily-metrics：回填按日发生量
  • GET /dashboard：读取原有近三日账号汇总
  • GET /overview?period=yesterday|7d|30d：读取完整自然日总览；可选 account_id 限定授权账号

相同幂等键不同内容返回 409；更新文章时附带当前 version。没有取得的数据请留空，不要填零。最近三天按北京时间今天及前两天计算，今天尚未完结。

文章生命周期与草稿

GET /articles 默认 status=published；可显式选择 drafting、illustrated、draft_saved、published、failed，不支持 all、空值或 null。fields=index 仍仅返回 id、title、account_id、platform、published_at 五项；草稿发布时间为 null。

旧 POST 不带流水线字段时保持 published，真实 url 和 published_at 仍必填。显式 status 或流水线字段进入草稿路径；省略 status 默认 draft_saved。所有非发布状态的 url、published_at 必须省略或为 null，不填占位链接或虚构时间；发布时再补齐真实值。未发布文章不进入发布统计、累计榜和到期提醒，文章级指标返回 409 ARTICLE_NOT_PUBLISHED；账号整体日数据不受影响。

PUT 携带当前 version，未传字段保留；sample、draft_ref、timings、reruns 为对象或 null，blockers、verify_items 为对象数组或 null。提供 JSON 时整字段替换，null 清空，不深合并；不接受字符串化 JSON 或 *_json。六字段序列化后 UTF-8 总大小最多 64KiB，每字段最多 12 层、4096 个值节点，未知合法子键保留，拒绝原型污染键。接口请求体原有限制仍生效（认证请求 256KB，公开模式写入 16KB）。draft_ref.pgc_id/appmsgid 保持字符串；timings.finished_at 为带时区时间；reruns.watchdog 为非负安全整数。已有文章级指标时不能改回非发布状态。普通 PUT 的整字段替换规则保持不变。

流水线合并与筛选

PATCH /articles 必须带 account_id，先验证账号授权，再按 run_dir 或完整的 (slot, run_date) 找记录。目录允许安全斜线分段，不扁平化；双键、账号、可选 id 或已存身份键冲突返回 409，整次不写入且不泄露冲突记录。创建的 version 省略或 0，匹配已有记录须带当前正版本；0 遇到已存在记录也返回 409。

PATCH 未传字段保留，对象 JSON 递归合并，数组整替换，顶层逻辑 JSON 的 null 清空整字段，嵌套 null 保留为 key:null；合并后仍遵守既有 JSON 总量、深度、节点与安全键限制，未知合法子键保留，JSON 数值必须有限。新记录默认 draft_saved；旧 POST 和普通 PUT 规则不变。返回 data 中的 upsert_action 为 created（201）、updated（200）或 unchanged（200）；当前版本且内容没变时不递增版本或更新时间。同一 Idempotency-Key 可重放相同请求；提交结果不明先 GET 已知 ID；没有 ID 则完整翻页相应账号和状态的文章列表，按目录或完整时段日期精确核对，不能换键盲目重发。

列表新增 slot、writer、has_warnings、has_pending_verify、series_no_min/max 筛选，始终与默认 status=published 等原条件取交集。布尔值只接受 true/false；编号上下界为正十进制安全整数且 min≤max。完整文章新增服务端派生 warnings 数组，索引仍五字段。仅检查已知数值：头条标题超过30个 Unicode 码点、字数不在2000–2300、小标题不在5–7、明确 zh/tt 时段图片少于25张；gzh 不检查图片，缺值不当零。时段不代表系统已配置排期。

verify_items[].done 规范为显式布尔值：true 已处理、false 待处理；历史缺失或不识别值保留为未知。任一 false 为 pending/true；空数组或全部 true 为 complete/false；null、缺失数组，或无 false 但有未知项为 unknown/null。has_pending_verify=true 仅筛选 pending，false 仅筛选 complete，未知不当作 false。完整文章返回 verify_state 和 has_pending_verify，索引不增加字段。

仅 draft_saved 检查草稿引用：头条用非空字符串 draft_ref.pgc_id，微信用 draft_ref.appmsgid，知乎和其他平台用合法 HTTP(S) 的 draft_ref.editor_url。未知键不当凭证，javascript/data 等协议不接受。链接中不接受用户信息、空白或控制字符。这里只核对格式，不访问外链，也不证明平台草稿存在或拥有编辑权限；缺失时追加 DRAFT_CREDENTIAL_MISSING 警告。

总览统计口径

总览默认昨天较前天；7d 为最近七个完整北京时间自然日较此前七日，不含今天。逐日优先账号整体数据；仅文章明细或混合来源不会与账号全量环比。某指标缺日则不可比较，真实零保留；前期零值的百分比为 null。累计复盘快照不会推算成每日新增数据，平台指标不跨账号混合。

文章提醒比较同账号、同平台、同发布年龄段的历史完整窗口，每篇其他文章最多一个样本，所有历史窗口都在本期开始前，天数与本期文章有效天数相同。年龄段为 D0、D1–2、D3–6、D7–13、D14–29、D30+；优先结束年龄最接近的窗口，再取较新窗口。至少五篇历史文章且中位数大于零，达到两倍或不高于一半才提示变化。先检查阅读，再检查平台单项互动，阅读正常不会隐藏互动异常；缺失或样本不足标为待积累。

totals 仍统计已登记的 published 文章及制作效率，due_reviews 保持 D1/D3/D7 复盘待办定义。data_status 仅将每日账号整体数据及阅读、原始点赞likes、评论均完整（approvals独立保留，不替代likes）的账号列为完整，提供完整/缺失账号 ID 和真实数据更新时间，不表示 AI 正在运行。旧 /dashboard 的今天加前两日口径保持不变。

累计统计与分页

文章列表默认保留全量 data 数组。传 page=1&page_size=20（1至200），或 limit=20&offset=0 启用分页，两种形式不能混用；envelope.meta 提供 total、unfiltered_total、has_more 等。排序在分页前完成，缺值始终排最后；支持 reads、likes、comments、approvals、latest_as_of、published_at、duration。新增 platform、topic（推断）、data_status 筛选。原 POST /articles、POST /observations 及其他写接口保持原路径、字段和返回结构。

总览 cumulative、platform_comparison、top_articles 始终独立按授权范围内 published 全库计算。top_n（1至100）和 top_platform 控制累计榜。每篇只取截至时间最近的一份快照，不按指标回填；没有数据为 null，真实零为 0。篇均分母为取得阅读的文章数。likes 保留原始点赞字段（知乎口径待核实），不映射为 approvals。各平台原始阅读计数相加不等于统一或去重人数。

30d 是两个等长30天完整北京时间窗口。publication_trend 为本站实际记录的发布量；数据不足不使用快照补零或插值。详情新增 nodes 和 timeline，单期不计算增长，零分母增幅为 null，负增长保留。日期待核实从原有备注明确标记派生，不写回日期，也不进入发布趋势或到期提醒。

原子日快照与完整日期索引

GET /api/v1/snapshot?date=YYYY-MM-DD 只接受一个明确有效的 date；GET /api/v1/snapshot/index 不接受查询参数。两者均只读，不写业务数据库或 Notion。快照是当前数据库对该业务日期的投影，不是历史时点备份。

这两个端点只接受用户等于明确 PUBLIC_BUSINESS_USER_ID 的有效 matrix_session，或在 PUBLIC_BUSINESS_MODE=1 时提供既有匿名公开范围。业务 owner 和既有日记 owner DAILY_NOTES_OWNER_ID 在私有模式也必须明确配置；不选择数据库首个用户。所有者会话保留全部账号可见性，匿名范围为既有配置账号加公开创建、减公开删除的账号。其他已登录用户返回403；任何 Authorization 头均返回403 SNAPSHOT_SESSION_REQUIRED，不支持 Bearer/API key，也不新增凭证权限。

响应外层为 data。日快照包含 snapshot_format、projection=current、date、scope_id、timezone=Asia/Shanghai、generated_at、content_hash；内部 data 包含 todos、templates、notes、accounts、articles、observations、daily_metrics、habit30days。notes 沿用既有公开日记归属，排除软删除记录且不含 memo。articles 包含目标日 run_date 草稿、该日发布和该日指标引用的文章，保留生命周期、null 与解码后的流水线 JSON。

habit30days 为目标日减29天至目标日的30个北京自然日：按每个当前有效模板计算关联未删除已完成待办的不同日期数，21天及以上为 habit，否则 todo。无该日业务时仍返回当前模板、账号框架和习惯窗口，其他数组为空。

索引成功时 complete=true，dates 按日期升序列出全部真实业务日期及逐日 content_hash，并提供 index_hash。日期来自待办、日记、文章 run_date/北京时间 published_at、观察 as_of、日指标 date；单有模板或账号不产生日期。不分页、不限制最近日期、不静默截断。稳定 SHA-256 排除 generated_at，包含 scope_id；对象键和实体集合规范化，嵌套业务数组保留顺序。模板、账号和习惯窗口依赖变化也会改变受影响日期哈希。

客户端核对「当前完整索引日期 ∪ 已保存日期」，重读变更日和已消失日期，覆盖旧日期修改、最后一条删除及日期迁移。scope_id 变化表示范围变化，必须重建基线，不能当成删除。单次请求包含鉴权的一致读取；索引和详情之间仍可能有写入，详情哈希与同范围索引不一致时应重新读取索引和受影响详情，应用前再核对索引，不能据竞争结果宣称同步完整。

单次预算：45次SQL（包括鉴权、修订检查与重试）、4000投影行、1MiB源投影JSON、1000日期、8MiB累计哈希输入、1MiB响应、累计 rows_read 100000；账号最多50个，业务读取每页200行。超限返回413 SNAPSHOT_LIMIT，无法核实读取回执返回503 SNAPSHOT_BUDGET，不返回部分结果。rows_read 是查询后观察值，不能充当查询前扫描或CPU硬上限，线上边缘CPU仍待验证。成功响应为 Cache-Control: private, no-store，Vary: Cookie, Authorization。

生活 / 工作碎碎念与兼容导出

旧 /daily-notes 省略 category 继续操作生活兼容项，旧内容原样保留，不自动分析分类。工作使用 ?category=work，读取、日期分页、PUT、DELETE及restore均按分类隔离版本与保存标识，旧请求及收据兼容。既有同源、公开编辑、限流及后台保护不变。

旧 /snapshot?date=YYYY-MM-DD 与 /snapshot/index 保持v1语义及生活哈希；增加 notes=all 明确读取双分类v2，生活在 data.notes，工作在 data.work_notes，v2索引包含只有工作记录的日期。完整备份为v8，包含工作记录与墓碑；v1–v7备份仍可恢复到空隔离库，不覆盖已有数据。现有Notion生活同步不改为自动发送工作内容。

多条碎碎念、工作提醒与主页映射

GET /api/v1/note-entries?category=life|work&date=YYYY-MM-DD 返回 data.entries 完整活动列表；默认 life 和北京时间今天，按 created_at、id 升序，每分类每天最多200条，超出完整读取上限返回503 NOTES_LIMIT，不截断。GET /note-entries/dates 按分类去重降序分页，before 为排除游标，page_size 默认30、最多100。旧 /daily-notes 兼容记录继续独立存在，不自动迁移或与新条目合并。

PUT /note-entries/{uuid} 恰好提交 {category,date,text,version,save_id}；创建 version=0，后续用当前版本，UUID/save_id 保持稳定。category/date 创建后不可改，正文纯文字最多64KiB，created_at/updated_at 为服务器实际保存时间，不接受 happened_at 或调用者时间。DELETE /note-entries/{uuid} 与 POST /note-entries/{uuid}/restore 提交 {version,save_id}；删除后须显式恢复。GET /note-entries/{uuid} 对编辑者保留墓碑全文，对普通读者隐藏删除项。GET /note-entries/operations/{save_id} 只向当前编辑 actor 返回 found 及版本、变更序号、哈希等元数据；未知保存先查收据再读条目，同时核对 id/version/content_hash，旧收据不能证明新版本由本次保存产生。相同标识不同内容409 IDEMPOTENCY_CONFLICT，版本变化409 VERSION_CONFLICT，不换键盲重试。

碎碎念和提醒固定归属 DAILY_NOTES_OWNER_ID。公开读取不改变归属；写入只允许该 owner 既有会话加同源 Origin/CSRF，或 PUBLIC_BUSINESS_MODE=1 的同源 X-Public-Business:1 请求。Bearer 不授予写入/收据权限，其他登录用户不能编辑。二者与旧日记共享每 owner 每分钟60次、每天2000次写入的实例级限制，超限429 NOTES_RATE_LIMIT，正文请求体最多256KiB。

GET /work-reminders?date=YYYY-MM-DD 返回 data.items，默认北京时间今天，最多100条活动提醒，超限413 WORK_REMINDERS_TOO_LARGE，不截断。PUT /work-reminders/{uuid} 提交 {date,source_key,summary,version,save_id}；summary 最多16KiB，source_key 为1–100个英数字或 _ . : -，日期及来源创建后不可改。同日同来源（含墓碑）唯一，重复用原 UUID 更新；不同 UUID 重复409 WORK_REMINDER_EXISTS。DELETE 和 POST /restore 使用同版本标记；摘要未变或删除/恢复状态未变时不推进实体版本，仍预留保存收据。这里只提供集合 GET，没有单项 GET 或收据端点；提醒数据不新建 cron 或外部推送。

GET /account-profiles 沿用账号授权范围返回主页映射，完整结果最多1000条，超限422 PROFILE_LIMIT_EXCEEDED。原 POST/PUT /accounts 增加可选 profile_url：支持头条、知乎、微信公众号公开主页，本地规范为 HTTPS 及 platform_identity，不访问外站、不执行平台登录；拒绝文章/后台链接、凭据、自定义端口及不安全字符。创建可从有效主页推断平台，显式平台须一致；同一规范身份在可见范围已登记则200、profile_reused:true，复用且保留原账号内容；范围外重复只返回409，不泄露账号。PUT 的 null/空串清除映射。账号写入仍用原管理员/公开业务权限，Bearer 不获得写权限。

独立工作台快照与 v9 备份

GET /api/v1/workbench-snapshot?date=YYYY-MM-DD 恰好接收一个明确有效日期，GET /api/v1/workbench-snapshot/index 无查询参数。两者均只读，格式为 haoduoyu-workbench-snapshot-v1，与已有 /snapshot v1、notes=all 的 v2 分开；原 Notion 同步及自动化不改动。使用既有明确业务 owner 会话或已开启的匿名公开范围，任何 Authorization 头403 SNAPSHOT_SESSION_REQUIRED；另须显式核实 DAILY_NOTES_OWNER_ID、MEMOS_OWNER_ID。todo 用业务 owner，生活/工作日记和提醒用日记 owner，memo 用备忘录 owner。

两个端点都返回 complete:true、scope_id、generated_at、manifest_hash、global_content_hash 和相同的全量 entities 元数据清单，包含所有日期、墓碑、无日期备忘录，按 entity_id 排序。稳定前缀为 todo:、legacy-life:、legacy-work:、note-entry:、work-reminder:、memo-group:、memo-note:；按 scope_id/entity_id 去重，不按正文或时间合并。来源 created_at/updated_at、version、可用 change_seq 与实体哈希保留；墓碑隐藏正文，memo 仍保留 group_id，分组删除产生有效子笔记墓碑，不虚构发生时间。

日期详情 data 为 todos、life_notes、work_notes、work_reminders、memo_groups、memos，含该日及全部无日期记录。索引 dates 升序且包括只有墓碑的日期，index_hash=manifest_hash；逐日索引哈希对应详情 date_content_hash，详情 content_hash 另含无日期正文。哈希排除 generated_at，规范对象键和实体顺序。范围变化必须重建基线；读取、应用前核对同范围完整 manifest 与全局/日期哈希，跨请求竞争时重新读取，不能凭单次旧索引宣称同步完整。

即使只选一天也完整读取全部来源；不设最近日期截断。整次预算含鉴权与重试：45次SQL、4000源行、1MiB源JSON、1000日期、8MiB累计哈希输入、1MiB响应、100000累计观察 rows_read、50账号，源读取每页200行。超限413 SNAPSHOT_LIMIT，缺可信回执503 SNAPSHOT_BUDGET，非法源数据503 SNAPSHOT_DATA；均不返回部分成功。rows_read 为查询后观察值，不是查询前扫描或CPU硬上限。响应 private,no-store，Vary: Cookie, Authorization。源写入上限另为每分类每天200条日记、每天100条提醒，备忘录沿用32分组/200笔记上限。

GET /api/v1/backup 仅管理员会话导出 haoduoyu-matrix-d1-v9，在 v8 上加入 note_entries、work_reminders、account_profiles，保留墓碑、来源修订及校验和；文章 CSV /export 不变。v1–v8 仍仅经显式允许运维工具恢复到空、未初始化的隔离库，新表默认空，不覆盖已有数据；没有 HTTP 恢复端点，不恢复旧会话和限流窗口。

AI reports

GET /api/v1/ai-reports?offset=0 and PUT /api/v1/ai-reports/{uuid}, and DELETE /api/v1/ai-reports/{uuid} are specified in OpenAPI. In PUBLIC_BUSINESS_MODE=1, public access needs no identity authentication. author is self-reported, not verified. Public writes require the site’s exact Origin, X-Public-Business: 1, and application/json. The PUT object contains only author and content. Put the work date YYYY-MM-DD on the first line of content as a client convention; the server does not enforce it.

The user has approved any visitor deleting any single report in public mode. Deletion is permanent and cannot be recovered; author signatures are self-reported and unauthenticated. Every list item includes content_hash, a lowercase SHA-256 digest of stable JSON over id, author, content and created_at. Send DELETE /api/v1/ai-reports/{uuid} with same-origin Origin, X-Public-Business: 1, and an application/json body such as {"expected_hash":"<content_hash from GET>","save_id":"<lowercase UUID for this operation>"}. A stale hash returns 409 VERSION_CONFLICT; reread the list before deciding whether to retry. The same identity repeating the identical request with the same save_id replays success, unless a record with that ID exists again (409). Reusing that save_id for a different request returns 409 IDEMPOTENCY_CONFLICT. A missing report returns 404. After deletion, PUT with the same report UUID returns 409 AI_REPORT_DELETED, preventing resurrection by a delayed create retry.

Use one lowercase UUID per report and reuse it with the same normalized body for retries: 201 creates, 200 returns the original, and different content returns 409 IDEMPOTENCY_CONFLICT. Lists return at most 100 records plus has_more; increase offset by 100. Author is 1–120 Unicode code points and content is at most 16 KiB UTF-8 after normalization and trimming; JSON requests are capped at 256 KiB. Public write attempts, including rejected bodies and retries, are limited per owner and module per process to 60 per minute and 2000 per UTC day; the limit is not global. Errors include 400 validation/JSON, 401/403 access, 404 route/UUID, 413 size, 415 content type, 429 AI_REPORTS_RATE_LIMIT, 500 internal error, and 503 configuration unavailable. Error responses contain error.code, error.message and request_id. Explicit invalid credentials do not fall back to public access. The configured owner session also works, with same-origin and CSRF required for writes; Bearer keys do not grant access.

内容复盘公开 API（独立模块）

一期入口 ?page=review&account=V字，固定展示 V字 / 头条。新资源使用 /api/v1/review，与旧图文 API 和后台数据独立，不自动迁移旧文章、观察或每日指标。页面提供读取展示，写入由 API 完成，没有页面编辑表单。业务内容由 Grok BOT 填写；以下JSON为空业务示例，不代表已有数据。

独立内容复盘模块；一期页面 ?page=review&account=V字。PUBLIC_BUSINESS_MODE=1时所有访客可读写四类公开资源，无身份认证，任何署名、来源或source_chat均不证明身份。沿用明确配置的日记owner，所有者会话也可用；显式无效凭证不回退匿名，Bearer不授予权限。旧 /articles、/observations、/daily-metrics 等API及旧数据独立，不自动迁入。

日期与北京时间

文章的 published_at 若为具体时间，所有分组、每日统计、文章库筛选、趋势归日及 API from/to 均先转换为 Asia/Shanghai（北京时间）再取日期，页面的具体时间也以北京时间显示。例如 2026-10-26T20:05:00Z 等于北京 2026-10-27 04:05，归入10月27日。BOT知道具体时间时应录入带 +08:00 的 ISO 时间，例如 2026-10-27T04:05:00+08:00；服务端仍规范存储为 UTC，不改动原业务时间。仅知日期时传严格 YYYY-MM-DD，原样保留，不伪造零点；未知传 null。snapshot_date、period_start、period_end、published_on 是纯日期，不加8小时；sent_to_gemini_at 的具体时间也以北京时间显示。

幂等、并发与永久删除

PUT用一个稳定UUID和相同规范化完整内容：新建201，相同200，不同409 IDEMPOTENCY_CONFLICT；缺省字段也参与比较。业务唯一冲突409 REVIEW_UNIQUE_CONFLICT带error.existing_id，先GET现有UUID核对。PUT不能覆盖修改，PATCH须当前expected_hash及至少一个可写字段；过期409 VERSION_CONFLICT，先重读核对。无实际变化的PATCH哈希不变；PATCH结果不明先GET，不自动使用新hash覆盖。

公开模式下任何访客均可永久删除，无法恢复。DELETE体为 {"expected_hash":"GET返回的content_hash","save_id":"本次操作的小写UUID"}。同一身份、相同save_id/路径/请求体重放200，不同请求409 IDEMPOTENCY_CONFLICT；缺失记录404，过期hash409 VERSION_CONFLICT。删除墓碑令旧UUID的PUT返回409 REVIEW_DELETED，防止延迟重试复活。有快照的文章须显式加cascade_snapshots:true，否则409 ARTICLE_HAS_SNAPSHOTS；级联永久删除所有关联快照并留下墓碑。没有restore接口。

快照批量创建

PUT /api/v1/review/snapshots:batch 体恰好为 {items:[{id,article_id,snapshot_date,...快照字段}]}，1–200项，每项须小写UUID。按序独立处理，HTTP200的data.items逐项含id、status及data或error；新建201、相同200、冲突409。须检查每项，失败不回滚先前成功项。重试保留原每项UUID和内容，不能把批次HTTP200当作全成功。
