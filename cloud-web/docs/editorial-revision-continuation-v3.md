# One explicitly approved unknown-revision continuation

This module allocates one independent, linked attempt for run `bd6d4434-273b-426e-a17f-9390fc124c84`, original requested structure revision `496c9348-7de3-4322-8462-55892b8162b0`, input SHA `666e17c577fcb127411d883f2ee6f4ac3b515c2698c950f870aec73af8854b35` only. Scope is `editorial_v3_one_explicit_unknown_revision_continuation`. It does not claim that the prior upstream request stopped, recover its outcome, or redefine ordinary retry permission.

The normal authenticated owner must explicitly accept the unknown prior outcome and potential additional charge. Request evidence contains the complete confirmation question and answer, both message IDs, exact quote SHA, `accept_unknown_prior_outcome: true`, and `executor_status: "unknown"`. An optional canceled Site request audit stores request/trace/ray IDs, outcome and wall duration only. It is not a signature or evidence of inferred start/end times. Neither user quotes nor audit IDs establish owner identity; normal authenticated dispatch does.

Preview is read-only and emits only binding hashes/identities. It makes no provider or configuration request. Authorization uses the strict runtime loader and current original authority/model/prompt/capability checks. The original stage must be requested, have the exact fixed input SHA, no artifact/text/partial/raw/terminal result, and an exact already-started revision HTTP delegation. The full candidate article, original completed author receipt, positive independent structural issues, initial fact report, full input, original snapshot and authority are checked.

The new input is identical to the original except `stage_id`, `round + 1`, and `sequence + 1`. A new nonce is allocated; no original token, stage, reservation, receipt or consumed delegation is changed. Unique owner/source and owner/key constraints enforce one grant per source for its lifetime.

Allocation is a four-statement D1 transaction: grant insert, claimed-stage insert, run round advancement, then a conditional NOT NULL assertion. Complete NULL-safe row CAS includes original run, authority, source stage, receipt, consumed HTTP delegation, article source/receipt and both reports. Balanced conjunctions stay under expression depth 100; one bound JSON array per row stays under 100 parameters. A late result before allocation or any partial allocation rolls back the new grant atomically.

The original complete HTTP delegation stays in its original table. The new grant records its exact full-row SHA plus frozen-JSON SHA/byte length and remaining row fields. Verification rereads the original row and computes those digests itself. This removes duplicated raw JSON without weakening row CAS or audit evidence. The original complete requested receipt image remains frozen. Original input is kept in the frozen source stage; the new complete input is kept once separately.

`verifyEditorialRevisionContinuationLineage(..., {mode})` distinguishes history from new execution. Legal requested usage/diagnostic progress is allowed after allocation; the old receipt's permanent response hash is not an execution lock. Both modes validate the original stage/input/snapshot/requested-model identity. History permits a legal late completed or failed receipt without deleting or ignoring it. Before a new paid start, such a terminal receipt returns `prior_terminal_changed`, `read_only: true`, and `new_execution_allowed: false`. This is a conservative reconciliation marker, not a statement that valid article text exists. Preview/authorization also return this read-only marker for an original terminal observed before allocation, including a late CAS race. Integrators must inspect `new_execution_allowed` before transport consumption/provider reservation and independently SQL-fence the original receipt's requested state to close late-result races.

The runtime's new-round fence must prevent an old worker from advancing the new current version. An old worker may still persist its own original receipt. After the new attempt starts, a late old result is historical and must not invalidate the new attempt's own immutable version or overwrite its outcome. No old late response is swallowed.

`isZeroContentBoundLateRevisionFailure` permits only diagnostic suppression for the original linked zero-payload late failure. It validates exact lineage and all content with `assertSafe`; actual credentials, nonempty raw/text, foreign stages or inputs are never exempted.
