## 发现与修复

1. **代理后共享登录限流额度。** 原代码直接用 `req.socket.remoteAddress` 为两个限流层级生成 bucket；反代部署时都是代理 IP。新增真实 HTTP 代理与两个回环客户端地址的回归，在原实现上复现不按客户端区分。修复后 `TRUSTED_PROXIES` 明确指定代理 IP/CIDR；默认忽略转发头。只从可信连接读取 `X-Forwarded-For`，从右至左停在首个不可信跳，规范化 IPv6 与映射 IPv4，拒绝非法或过长链。转发头不能影响 Origin、CSRF 或安全 cookie 判断。10 次组合额度和 100 次 IP 总额度保持原值，窗口为 15 分钟。
2. **备份会覆盖既有文件。** 原备份脚本对已有目标返回成功并替换其内容。新增回归在原实现上复现。现以 `wx` 独占创建，首字节前权限为 `0600`；已有文件、符号链接、硬链接及同源目标均拒绝。备份失败清理本次未完成输出；已有目标内容不变。额外以宽松 umask 验证最终文件 `0600`、新父目录 `0700`，以损坏的合成源库验证失败清理。

没有改动业务 schema、指标聚合、累计快照追加规则或审计规则。

## 未验证与上线最小缺项

本轮没有付费服务、真实凭据、持久账号授权或生产操作；没有部署阻断来自代码测试，但以下上线条件尚未具备或未验收：

1. **长期托管目标。** 需要确定允许单实例 Docker 与本地持久卷的主机、存储容量及访问方式；本轮没有购买服务器或建立托管账号。
2. **独立域名和 HTTPS 链路。** 需明确新站域名、实际反代拓扑、证书及 `SITE_ORIGIN`，按真实连接对端配置最小 `TRUSTED_PROXIES`。本地 HTTP 转发与 `Secure` 响应头检查不等于真实 HTTPS 浏览器验收；目标链路需从两个客户端重测限流、登录、退出、改密码及 CSRF。
3. **持久化运维。** 需设置实际数据/备份卷的访问权、备份调度、保留期限及独立故障域存储，并在目标主机执行恢复、切换和回退演练。没有用本轮临时卷代替长期存储。
4. **管理员和可选执行器。** 上线时由用户通过 CLI 设置真实管理员密码。若需要 Grok 等回填，另建最小范围可撤销 key，在真实执行器完成“查询—登记—回读—幂等重试—越权拒绝—撤销拒绝”验收；本轮只有合成 Bearer 客户端验证，没有真实接入。

浏览器布局、XSS 页面交互仍引用首轮证据，本轮未重做浏览器 QA；没有声称生产 HTTPS、外部平台自动采数或真实 Grok 接入已经通过。
