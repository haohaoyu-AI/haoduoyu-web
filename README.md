# 好多鱼图文（文章总库）

> 本库原名「文章总库」；文中「总库」即指本项目根目录。

一个总入口：在控制台完成选题、确认配图关键词、搜图审图、Word 排版和草稿投递。当前主流程是：

```
选题灵感：热榜选题或自己出题
       └─ 同次生成写作提示词 + 配图关键词清单 → 人工确认关键词
                        ├─ 把提示词交给写作模型，写成 Word（配图搜索不需要 Word）
                        └─ 选定图源，按确认的关键词搜图 → 人工保留/去掉
                                             ↓
                         将对应 Word 放入该选题的标题图片文件夹
                                             ↓
                  按正文段落匹配配图并生成成稿.docx + 预览
                                             ↓
                一键送入所选平台草稿箱，核对后在平台人工发布
```

## 目录

| 目录 | 放什么 |
| --- | --- |
| `选题\` | 选题系统的家：写作画像、每次选题任务单、审稿口令、每日单篇提示词、实战拆解 |
| `选题\阅读分析\` | 自己历史作品的语料、作品目录（选题时查写过什么） |
| `选题\参考\十年影评代表作\` | 代表作原稿与风格分析 |
| `未排版文章\` | 新版选题包、按选题标题导出的图片和旧版待处理 Word 稿 |
| `已排版文章\` | 排好的成稿，一个主题一个文件夹（含 `原始素材\` 备份） |
| `素材\` | 头像、历史配图这类公用素材 |
| `data\` | `平台设置.json`（各平台目录）+ `发布规则.json`（发文时间表规则）+ `库.json`（总库台账），不要删 |
| `预览\` | 总库预览网页 |

平台目录分别存放待发/已发文章、平台草稿助手和回执：

| 平台目录 | 内容 |
| --- | --- |
| `平台\今日头条\` | 今日头条待发/已发目录、草稿助手和回执；详见该目录的 README |
| `平台\知乎\` | 知乎待发/已发目录、登录/保存草稿脚本和回执 |
| `平台\百家号\` | 百家号待发/已发目录、登录/保存草稿脚本和回执 |

实际平台根目录由 `data\平台设置.json` 指定，可以按需调整。

## 当前主流程：从选题到发布

双击桌面「好多鱼自媒体图文管理系统」，或运行 **00-打开控制台.cmd**。文章从「选题灵感」开始；模型接口在「设置」管理。

1. **选题并生成两份独立材料**：选择快速/深度选题并确认推荐卡，或在「我有选题」中输入自己的选题；给得到大脑的内容固定为“什么事、值得写、特殊要求、建议标题”四行，具体写法和标题定稿由专家写作团判断。系统同时生成本地配图关键词清单，但复制文章简报时不会带上它。
2. **确认配图关键词**：核对并编辑清单，再点击「确认关键词并导入配图清单」。核心词来自原始选题，默认启用；主体素材词和背景词是可选建议，默认关闭，只有确认启用后才会搜。文章简报和配图词彼此独立，配图词不是从文章简报或之后的 Word 正文中提取的。
3. **写稿、搜图可先后进行**：把四行文章简报交给「得到大脑·专家写作团」，完成后保存为 `.docx`。配图搜索不需要 Word：在「配图排版」选择图源，并设置文本相关性筛选和正文位置匹配模型，再按已确认的词搜图；文字模型先按搜索词和来源文字筛候选，你再逐张放大查看并点「保留」或「去掉」。搜索不会自动换图源、改关键词或生成 AI 图片。保留的图片会同步到 `未排版文章\<标题>\` 图片文件夹；配图清单可按单条关键词再次搜图。
4. **导入 Word 并生成成稿**：把对应文章的 `.docx` 放进该标题图片文件夹，然后点击「排版生成定稿」。新版按已保留图片和 Word 正文匹配位置，图片只放在正文段落之后，不自动设标题下封面；模型不能可靠匹配的图片会跳过。若模型匹配失败，程序回退到本地规则，按小标题分组放在不同正文段落之后。至少保留一张图片才能在新版流程中生成定稿。成稿位于 `已排版文章\<标题>\`，并带 `配图\`、`配图清单.json`、`原始素材\` 和 `预览.html`。
5. **送草稿并人工发布**：在「平台发布」勾选平台并点击「一键送草稿箱」。系统逐个平台分发并保存到草稿箱；已有成功记录的稿件会跳过，失败或保存结果不明的稿件保留待核对状态，一个平台出错不会阻止后续平台。打开平台草稿核对标题、正文和图片，再由你在平台后台确认发布。也可在「分发中心」只把成稿复制到平台待发目录，再用平台目录中的旧式草稿助手处理；一键送草稿不要求预先分发。

新版的实际配图张数由你逐张审核决定；启用关键词数只作为计划配图数，至少保留一张才能生成定稿。关键词上限和每轮搜图候选设置见下文「配图与排版规则」。

时间表是发布计划参考：用 **13-给新稿排期.cmd** 排期、**12-查看发文时间表.cmd** 查看。当前规则在 `data\发布规则.json`；实际发布后用 **14-登记已发布.cmd** 登记时间，后续平台时间按规则顺延。

### 旧版 Word 配图入口（兼容/备用）

旧版 Word 配图仍作为兼容/备用入口，供传统 Word 稿使用；新旧入口的差异见下文「配图与排版规则」。

双击 **04-查看总库状态.cmd** 可查看每篇稿子的排版、平台草稿和发布进度。


## 标题里的平台后缀

调取出去以后，总库里的标题会自动缀上平台简称，一眼看出这篇到过哪儿：

| 情况 | 总库里显示 |
| --- | --- |
| 还没调取 | `文章A` |
| 调取给头条 | `文章A（头条）` |
| 调取给知乎和头条 | `文章B（知乎头条）` |
| 三家都调取 | `文章C（知乎头条百家号）` |

顺序固定是 知乎 → 头条 → 百家号。`04-查看总库状态.cmd`、`05-生成总库预览.cmd` 和
`data\库.json` 里的「分发平台」都按这个来；只在平台发过文（有回执）没在总库调取的，也算数。


## 发文时间表

默认一篇稿子先排今日头条首发，知乎和百家号按间隔时间排在后面；实际规则可在 `data\发布规则.json` 修改。
总库按这个规则排时间，双击 **12-查看发文时间表.cmd** 就能看到整张表：

```
时间              平台           文章                          状态
10-01 周四 20:00  今日头条·首发  家中搜出300根金条…            ⏳等到点
10-02 周五 20:00  知乎           家中搜出300根金条…            🔒等首发
10-02 周五 20:00  百家号         家中搜出300根金条…            🔒等首发
```

状态的含义：

| 状态 | 意思 |
| --- | --- |
| ⏳等到点 | 还没到计划时间 |
| ⚠️该发 | 到点了，该发了 |
| 🔒等首发 | 首发平台还没登记实际发布时间，按规则先压着 |
| ✅已发 | 已经登记过实际发布时间 |
| ❌未排期 | 还没排期，双击 13-给新稿排期.cmd |

规则写在 `data\发布规则.json`，随时可以改：

```json
{
  "首发平台": "今日头条",
  "发布时间": "20:00",
  "间隔小时": { "今日头条": 0, "知乎": 24, "百家号": 24 }
}
```

- `首发平台`：先发哪家；
- `发布时间`：排期默认几点发，也是只写日期时的时刻；
- `间隔小时`：其他平台比首发晚多久；改成 `6` 就是当天接着发，改成 `48` 就是隔一天。

改了规则想重排，用 `python -X utf8 -m article_hub 排期 --重排`（只清计划，已经登记的实际发布时间不动）。
网页版是 `05-生成总库预览.cmd` 一起生成的 `预览\发布时间表.html`。

## 配图与排版规则

### 新版：按选题关键词搜图

新版只读取已经确认并导入的选题配图清单；搜图阶段不读 Word、不改写关键词，也不会自动换图源或生成 AI 图片。可选择一个或多个图片来源；新版使用配图页当前勾选的图源，系统不会自动切换图源。候选先按确认的关键词及来源文字筛选，再由你放大图片并逐张保留或去掉。关键词/来源文字匹配不能证明实际画面准确，定稿前请核对图片内容、来源和使用权。

- 清单最多 8 个词：最多 5 个核心词、最多 3 个可选扩展词；核心词默认启用，主体素材词和背景词默认关闭。
- 启用词数决定本篇计划配图数，但计划数不是硬门槛。每轮候选目标在页面可选 8、12 或 20 张，默认 20；每轮检查最多 80 条来源候选并受时间预算限制。可按关键词继续搜图；至少保留一张才可生成成稿，没有统一的 7 张或 9 张最终上限。
- Word 放进同一标题的图片文件夹后，排版模型依据已保留图片的来源标题、搜图词和正文，为图片匹配不同的正文段落。新版不把第一张图当成标题下封面；图片按正文阅读顺序插在段落之后。模型无法可靠匹配的图会记为未使用；协作匹配失败时改用本地规则，按小标题分组并放在未占用的正文段落之后。
- 成稿保留源稿内容和样式，在对应成稿目录输出 `<标题>.docx`、`配图\`、`配图清单.json`、`原始素材\` 与 `预览.html`。如果 Word 有程序不支持的结构，排版可能失败；请按页面或报错处理后再试。

### 旧版：按 Word 正文搜图（兼容/备用）

传统 Word 入口仍在控制台折叠区，以及 `06-自动配图.cmd`、`08-先看搜索词.cmd`、`article_hub 配图/关键词` 命令中。它先读 Word 标题、小标题和正文提取搜索词，再按正文和关键词找图、安排封面与正文图片；`07-登录小红书.cmd` 用于该流程的小红书图源。旧版会生成 `搜索词.txt`、`配图顺序.txt`、`配图清单.json` 和 `配图来源.md` 等工作文件，供手动检查和修改。

旧版自动配图按正文结构计划 5—20 张，计划数不是人工定稿的硬门槛；命令行 `配图` 与 `排版` 的 `--最多图片` 默认值是 7，而底层 `layout.format_topic()` 的默认值是 9，控制台人工审核排版则按已保留数传入上限。因此 7 或 9 都不是整个系统的统一上限。旧版排版会将封面放在标题下，其余图片排在正文段落之后；新选题主流程不使用这套封面和 Word 取词逻辑。

新版图片与旧版搜索结果都来自所选图源；可下载不等于可转载。发稿前应检查图片内容、来源与平台规则。


## 命令行

```powershell
python -X utf8 -m article_hub 关键词                 # 列出每篇稿子的关键词和配图搜索词
python -X utf8 -m article_hub 选题                    # 抓头条热榜，挑 3 条候选并写提示词
python -X utf8 -m article_hub 控制台                  # 打开可视化控制台
python -X utf8 -m article_hub 控制台 --不打开 --端口 8765   # 只起服务，不弹窗口
python -X utf8 -m article_hub 关键词 --only 主题名    # 只看一篇（已排版的也能查，只读）
python -X utf8 -m article_hub 关键词 --覆盖           # 搜索词.txt 已有也按自动结果重写
python -X utf8 -m article_hub 配图                   # 旧版 Word 配图入口；默认 --最多图片 7
python -X utf8 -m article_hub 配图 --only 胖东来四年合同   # 只处理一个主题
python -X utf8 -m article_hub 配图 --只生成搜索词     # 只写 搜索词.txt，先不搜图
python -X utf8 -m article_hub 配图 --来源 今日头条    # 旧版仅使用头条图源
python -X utf8 -m article_hub 配图 --不排版 --force   # 只把图配进未排版文件夹，不出成稿
python -X utf8 -m article_hub 登录小红书              # 打开专用 Edge 登录一次
python -X utf8 -m article_hub 排版                   # 旧版 Word/图片目录排版，默认最多 7 张
python -X utf8 -m article_hub 排版 --only 电话诈骗    # 只排一个主题
python -X utf8 -m article_hub 排版 --force            # 旧版成稿已存在时重新生成
python -X utf8 -m article_hub 状态                    # 查看总库进度
python -X utf8 -m article_hub 时间表                   # 按时间列出每篇发到哪个平台
python -X utf8 -m article_hub 排期                    # 还没排期的稿子排上时间
python -X utf8 -m article_hub 排期 --从 2026-10-01     # 从指定日期开始排
python -X utf8 -m article_hub 排期 --重排              # 清掉计划重排（实际发布时间不动）
python -X utf8 -m article_hub 排期 --主题 主题名 --时间 "2026-10-01 20:00"
python -X utf8 -m article_hub 记发布 --主题 主题名 --平台 今日头条            # 默认记成现在
python -X utf8 -m article_hub 记发布 --主题 主题名 --平台 知乎 --时间 "2026-10-02 20:05"
python -X utf8 -m article_hub 调取 --平台 知乎         # 调取给某个平台
python -X utf8 -m article_hub 调取 --平台 今日头条     # 调取给头条
python -X utf8 -m article_hub 调取 --平台 全部         # 三家一起调取
python -X utf8 -m article_hub 调取 --平台 百家号 --only 电话诈骗
python -X utf8 -m article_hub 预览                    # 生成总库预览网页
python -X utf8 -m unittest discover -s tests -v       # 跑单元测试
```

## 说明与注意

- 新版会把选题包和审阅素材复制到成稿目录的 `原始素材\`；旧版命令行排版成功后会把源主题文件夹移入 `原始素材\`。失败时按控制台提示处理。
- 旧版命令行遇到同名成稿默认停止，确认重排时加 `--force`；新版在配图页点击「重新排版生成定稿」可替换当前定稿并保留备份。
- 旧版直接排版要求主题文件夹中只有一份 Word。新版图片标题文件夹如有多份 `.docx`，请在该篇卡片中选定要绑定的一份。
- 含表格的 `.docx` 当前不能用于排版，会明确报错；其他无法读取或复用的 Word 结构按程序提示处理。
- 成稿沿用源稿样式；万一源稿结构没法原样沿用，程序会退回标准样式并在提示里写明，
  这时请自己确认标题和小标题的样式。
- `data\平台设置.json` 记录各平台目录（知乎 / 今日头条 / 百家号），换电脑或改路径时改这里即可。
- `data\库.json` 是总库台账（排版时间、调取记录、分发平台、发文回执），不要删除。
- `data\发布规则.json` 是发文时间表的规则（首发平台、发布时刻、间隔小时），改完用 `排期 --重排` 生效。
- `data\小红书配置` 是搜图用的专用 Edge 登录状态，删了要重新扫码登录；和日常 Edge 互不干扰。
- 根目录散落的 Word 由旧版 **06-自动配图.cmd** 整理；按主题管理时，可先放入 `未排版文章\主题\` 文件夹。
